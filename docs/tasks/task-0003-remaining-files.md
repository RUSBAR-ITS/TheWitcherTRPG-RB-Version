## Результат

Подробные карточки всех оставшихся файлов исследуемого среза в согласованных границах, заполненный реестр и проверенные связи между файлами. Материалы размещаются в `docs/analytics/code-audit`.

## Согласованные требования

- Работать небольшими связанными порциями, ориентировочно по 5–10 файлов; крупные файлы при необходимости разбирать отдельно.
- Применять шаблон карточки и таблицу зависимостей из TASK-0001.
- Разобрать оставшиеся после TASK-0002 файлы из `module/`, `templates/`, CSS из `styles/`, `lang/`, `packsJson/`, `utils/`, а также `system.json`, `package.json` и `build.json`, если их описание ещё не завершено.
- Применять [согласованные исключения TASK-0001](task-0001-code-inventory.md#согласованные-исключения): каталоги `docs/`, `assets/`, `.github/`, `.git/` исключены целиком; их содержимое и перечисленные служебные файлы не получают строк реестра или отдельных карточек. При выполнении сверяться с перечнем, перенесённым в README исследования.
- Исключённые файлы можно использовать как справочные источники; это не включает их обратно в объём анализа. Новые исключения требуют согласования.
- После каждой порции выполнять перекрёстную сверку, обновлять карточки, реестр и журнал проверок.
- Найденные проблемы регистрировать в `docs/issues/potential` по разрешению пользователя; подтверждение и исправление согласовываются отдельно.

## Что уточнить и разбить на подзадачи

После TASK-0002 согласовать группы файлов и их очередность по фактическим зависимостям, перечень каждой порции с учётом утверждённых исключений, критерии приёмки и необходимые проверки. Для подзадач использовать следующие свободные ID общего реестра, связывая их с этой задачей.

Конкретные группы и подзадачи пока не созданы. Статус `draft` означает заготовку, которую нужно расширить перед выполнением.

## Проверки и приёмка

Точные сценарии и критерии определяются в подзадачах. Обязательная основа — сверка описаний с исходниками, проверка определений и потребителей, полноты порции, ссылок и версии исследуемых файлов. Полнота оценивается в согласованных границах; исключённые файлы не считаются пропусками и не добавляются в карточки порции.

[Заготовка общей сверки](task-0004-cross-checks.md) дополняет проверку каждой порции, а [итоговая проверка](task-0005-final-coverage.md) оценивает весь срез.

### Технический разбор компедиумов

Проверяются экспортные данные packsJson и их взаимодействие с текущим движком. Соответствие текста/чисел рулбукам, переработка правил, редактирование переводов и исправление контента не входят в задачи. Содержимое packs/ остаётся вне пофайлового анализа; источники JSON и установленная БД не объявляются одинаковыми без отдельной проверки.

Шесть наборов RollTable разбираются целиком: 128 файлов и 995 вложенных результатов. Critical Wounds разбит по существующим папкам: 94 Item и четыре Folder, 79 эффектов и 360 changes. Это подсчёт сохранённых структур при постановке задач, не результат проверки их поведения.

1. Для каждого JSON создать отдельную карточку с повторением исходного пути. Вложенные TableResult, ActiveEffect и changes описать внутри файла-владельца; повторяемый контракт можно связывать ссылкой, но особенности каждого файла перечисляются явно.
2. Массовый проход по общей схеме должен охватывать все файлы/вложенные записи. После него отдельно разобрать исключения и провести сверку внутри порции; выборка одного похожего файла не заменяет остальные.
3. Проверять ID/_key/папки, типы, формулы, диапазоны/веса, ссылки и фактических потребителей. Для травм дополнительно проследить эффекты, пути полей, состояния и followUp; значения сравнивать с техническим контрактом модели, а не с предполагаемыми игровыми правилами.
4. Различать исходный JSON, результат штатной очистки/миграции и данные действующего мира. Старое имя поля не считать ошибкой до проверки обработки установленным Foundry. Точный файл/версию ядра фиксировать при выполнении.
5. Для каждой связи указывать источник/получателя и способ использования: загрузка, ручной draw, вложенный roll, ссылка для перехода или фактическое изменение Actor/Item. Текст результата, содержащий бонус, сам по себе не считается автоматизацией.
6. Проверять прямые и обратные ссылки. Ссылки во внешний мир/пакет и ещё не описанные документы помечать с пределами проверки; отсутствие локальной цели не всегда означает ошибку внешнего источника.
7. После каждой порции — сверка с исходниками, соседними карточками и issues. .056 дополнительно сверяет пять наборов генерации (117 файлов); .057 — все RollTable (128 файлов); .061 — весь criticalWounds (98 файлов) и все семь компедиумов (226 файлов) с движком.
8. При необходимости допустимы изолированные проверки через stdin с настоящими моделями/ядром и явными фасадами записи. Сборка/извлечение, установка зависимостей, HTTP, изменение миров/БД, прав и исходных JSON в эти задачи не входят.

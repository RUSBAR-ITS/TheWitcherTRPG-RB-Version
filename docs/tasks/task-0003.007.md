## Проблема и результат

После TASK-0002 файлы этой порции имеют статус «Не начат». Просмотр отдельных определений при планировании не считается завершённым анализом.

Две подробные карточки центрального документа Actor и modifierMixin: порядок подготовки, применение эффектов, основные действия и карта делегирования другим файлам.

## Границы и требования

Применяются [общие требования TASK-0003](task-0003-remaining-files.md#общие-требования-к-каждой-подзадаче), [шаблон карточки](../analytics/code-audit/templates/file.md) и [согласованные исключения](../analytics/code-audit/README.md#согласованные-исключения). Все файлы таблицы разбираются полностью; исходники используются для чтения.

Полный разбор всех mixin-файлов Actor, кроме modifierMixin, откладывается. Проверка определения вызываемого метода нужна для связи, но не завершает анализ его файла.

Ссылки и вызовы в соседних файлах проверяются до определения используемой сущности. Такой просмотр не создаёт карточку соседнего файла и не меняет его статус на «Проверено». Исправления системы, изменения игровых правил и данных не входят в эту задачу.

## Порядок разбора

1. Разбирать witcherActor.js по разделам, но завершить карточку только после чтения всего файла: импорты и класс, подготовка данных, применение эффектов, действия с предметами и остальными данными, подключение mixin-файлов.
2. Описать порядок собственных и родительских вызовов подготовки, источники значений и последовательность применения ActiveEffect по коду текущей версии.
3. Для каждого Object.assign и вызова метода, добавляемого извне, найти файл определения; различать собственный метод класса, примесь и API Foundry.
4. Полностью разобрать modifierMixin: получение данных из skillMap и Actor, сборка строк формул, настройка показа подробностей, имена эффектов и групповые модификаторы.
5. Установить вызовы методов через game.TheWitcherTRPG, Queries и другие динамические маршруты, относящиеся к документу Actor; не ограничиваться импортами.

## Проверки

- Сопоставить читаемые и изменяемые поля с карточками моделей из TASK-0003.001–TASK-0003.006.
- Проверить место применения эффектов относительно вычисляемых данных и условия ветвлений; записать, какие участки принадлежат ядру Foundry и какая версия API проверена.
- Для смешанных модификаторов и отключённых/переносимых эффектов проследить фактическую последовательность по исходникам. Ожидания брать из кода и API; изменение порядка вычислений не является результатом этой задачи.
- Сверить имена подключаемых методов с определениями mixin-файлов, а dynamic dispatch — с уже описанными queries и точкой входа.

После содержательной сверки проверить соответствие каждого описания его исходнику, наличие всех карточек порции, ссылки, статусы и двустороннюю согласованность с уже описанными зависимостями. В [журнале](../analytics/code-audit/review-log.md) записать фактические команды или сценарии, результаты и непроверенные участки.

По умолчанию выполняется статический анализ. Изолированное выполнение исходных функций допустимо для проверки существенного спорного поведения с явным описанием подмен API. Запуск мира, запись в игровые документы, сборка и создание тестового стенда не входят в поручение. Применяются [правила проверок](../rules/testing.md).

## Результат

Проверить, что созданный справочник действительно помогает находить текущий код и его окружение, и подготовить обоснованную следующую очередь. Это приёмка нового инструмента и его записей, а не повтор TASK-0004.

## Проверочная выборка

| Запрос / случай | Что сверить независимо от результата инструмента |
| --- | --- |
| IQ-01: термин характеристики/навыка и точное имя | Подходящие сущности и роли, различение неоднозначных совпадений |
| IQ-02: activeEffectModifiers | Определения и владельцы в границах пилота |
| IQ-03: skillListener и регистрация Actor | Условие входа, регистрация/вызов и предел охвата |
| IQ-04/IQ-05: rollSkillCheck | Исходящие связи, реальные входящие потребители и направления |
| IQ-06: поле навыка / характеристики | Читатели, писатели, вычисляемые и подготовленные значения |
| IQ-07: метод/поле из .004 | Процесс, шаг, ветвь, соседние шаги и подробности |
| IQ-08: сущность со связанным issue | Правильный документ, поздние уточнения, доказательство и версия |
| Одно имя, динамическая цель, цикл, пустой и частичный ответ | Явные различия, конечный обход и сообщение об усечении |
| Несовпадение версии источника | Запись помечается согласно контракту; источник не изменяется ради теста |

Ожидаемые адреса и существенные связи получать из кода/проверенного аудита до сопоставления с выдачей. Для проверки устаревания использовать отдельный тестовый вход метаданных.

## Порядок работы

1. Выполнить документированный запуск всех восьми запросов; сохранить короткие примеры и точные команды.
2. Сопоставить результаты с независимыми ориентирами; перечислить пропуски, ложные связи, лишнюю выдачу и неясные границы.
3. Исправить ошибки записей/инструмента в согласованном контракте и повторить затронутые проверки. Новое решение о формате сначала согласовать.
4. Проверить применимость сведений, ссылки, обе стороны отношений и покрытие пилота. Полноту пилота оценивать по выбранным областям, а не по числу файловых узлов.
5. Сопоставить реестр 615 файлов с покрытием: выделить области внутри 23 основных файлов, которые остались вне пилота, остальные файлы и ранее заведённые граничные записи.
6. Подготовить предложение следующих порций по логическим блокам с конкретными файлами/областями и ожидаемыми запросами. Учесть шаблоны, en/ru, данные и UUID компедиумов, не сводить остаток к JavaScript. Следующие подзадачи оформляются после согласования очереди.

Отчёт о пригодности и остатке, примеры запросов, текущий индекс/инструкция и затронутые проверки; TASK-0006, эта подзадача, указатели и CHANGELOG. Новые записи issues/задачи исправлений не создаются автоматически. Полный графический интерфейс не является критерием пилота.

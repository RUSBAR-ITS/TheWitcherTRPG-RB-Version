## Проблема и результат

После TASK-0002 файлы этой порции имеют статус «Не начат». Просмотр отдельных определений при планировании не считается завершённым анализом.

Восемь карточек интерфейса эффектов и проверенные цепочки: действие пользователя → обработчик → сохранённые поля → применение, с явными границами системного кода и ядра Foundry.

## Границы и требования

Применяются [общие требования TASK-0003](task-0003-remaining-files.md#общие-требования-к-каждой-подзадаче), [шаблон карточки](../analytics/code-audit/templates/file.md) и [согласованные исключения](../analytics/code-audit/README.md#согласованные-исключения). Все файлы таблицы разбираются полностью; исходники используются для чтения.

Полный разбор базовых и специализированных листов, CSS и локализаций будет продолжен далее. Внешние шаблоны Foundry используются как справочные источники, без строк в реестре системы.

Ссылки и вызовы в соседних файлах проверяются до определения используемой сущности. Такой просмотр не создаёт карточку соседнего файла и не меняет его статус на «Проверено». Исправления системы, изменения игровых правил и данных не входят в эту задачу.

## Порядок разбора

1. Полностью разобрать конфигурацию эффекта: PARTS, actions, подготовку контекста, рендер, wizardAction, autocomplete и подключение обоих mixin-файлов.
2. Перечислить группы подсказок, генерируемые пути, значения и режимы; проверить способы выбора схемы Actor/Item и тип эффекта, для которого доступны подсказки.
3. Проследить содержимое мастера и поля вкладки системных параметров до записи документа. Различить поля эффекта в целом и свойства отдельных changes.
4. Разобрать группировку и управление эффектами с листа: создание, открытие, изменение активности и удаление по фактическим обработчикам.
5. Для каждого из четырёх шаблонов описать контекст, помощники, включения, selectors/data-action и принимающий обработчик. Отдельно обозначить шаблоны ядра Foundry как внешние зависимости.

## Проверки

- Для кнопки мастера проследить регистрацию действия, открываемую форму, чтение значений и обновление changes. Проверять текущий код, не предполагать наличие ограничений по названию поля.
- Сверить каждую группу подсказок с существующими путями моделей либо обозначить неустановленную связь; проверить варианты обычного эффекта и временного улучшения по фактическим типам.
- Проверить соответствие управляющих элементов шаблонов обработчикам и их регистрации в использующих листах. Чтение mixin-файла само по себе не доказывает, что действие подключено.
- Сверить интерфейсные поля с моделями и применением из TASK-0003.009; зафиксировать состояния, которые можно сохранить, но применение которых ещё не доказано.
- Провести заключительную сверку связей всех первых десяти порций с TASK-0002; отложенные связи перечислить с точными файлами и способом проверки.

После содержательной сверки проверить соответствие каждого описания его исходнику, наличие всех карточек порции, ссылки, статусы и двустороннюю согласованность с уже описанными зависимостями. В [журнале](../analytics/code-audit/review-log.md) записать фактические команды или сценарии, результаты и непроверенные участки.

По умолчанию выполняется статический анализ. Изолированное выполнение исходных функций допустимо для проверки существенного спорного поведения с явным описанием подмен API. Запуск мира, запись в игровые документы, сборка и создание тестового стенда не входят в поручение. Применяются [правила проверок](../rules/testing.md).

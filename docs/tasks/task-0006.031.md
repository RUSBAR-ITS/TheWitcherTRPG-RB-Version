## Порядок работы

1. Сопоставить поля трёх типов магических Item с зарегистрированными листами, общими редакторами и доступными действиями; не переносить метод SpellData на HexData по сходству имени.
2. Связать source миграции со схемой и prepared данными: текстовый effect, структурированные воздействия, ActiveEffect, damage/defense/consume/region имеют разные контракты.
3. Проследить два набора UUID компонентов ritual: подготовка → HBS → drop/edit/remove → update. Ссылку на компонент и количество отличить от фактического расходования при cast.
4. Соединить form input с точным полем и reader castSpell/region; задокументировать нужный core submit/UUID cleaning либо внешнюю границу.

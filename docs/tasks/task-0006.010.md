## Порядок работы

Применяются [общие требования расширения](task-0006-system-index.md#общие-требования-к-расширению-006011), формат v1 и существующие постоянные ID.

1. Связать параметры открытия type/skillKey, PARTS и контекст с lookup/input.name. Явно отметить общую ссылку context.config на CONFIG и её изменения, если подтверждены кодом.
2. Разделить editable value/unmodifiedMax/флаги и disabled activeEffectModifiers: отображение бонуса не является его писателем.
3. Описать submitOnChange, явные update и ручные ресурсы/сбросы; показывать payload/целевой документ и переход к prepared-расчётам через внешний lifecycle.
4. Для старого customSkillMixin проследить Item lookup, систему modifiers, ID/индекс элемента, строки input и типы значений. Сопоставить наличие поля/валидации со схемой и существующими issues, без исправления игровой логики.
5. Добавить процессы формы характеристик/навыков и старого списка custom-модификаторов; входы из .009 использовать повторно, несовпадения/отмену/внешнее сохранение обозначить.
6. Перекрёстно сверить имя поля HBS → callback или submit → схема/читатель; проверить отсутствие ложного writes у disabled input.

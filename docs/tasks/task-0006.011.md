## Результат

По точному ключу или подписи en/ru находить документ/раздел определения, соответствие между языками и уже проверенные места использования. Связать локализации с расширенными UI/settings без повторного переписывания всех текстов аудита.

Итог этой задачи — записи справочника и проверяемые примеры поиска. Исходники в таблицах используются для чтения. Игровое поведение, документы мира и содержимое компедиумов не изменяются.

## Порядок работы

Применяются [общие требования расширения](task-0006-system-index.md#общие-требования-к-расширению-006011), формат v1 и существующие постоянные ID.

1. Сопоставить текущие словари с карточками, сохранив регистр, точки, вложенность и повторяющиеся подписи. Не применять свёртку ключей, которая теряет реальные различия.
2. Обеспечить адресуемость всех ключей двух словарей: отдельными значимыми сущностями или явными группами с точными ключами/адресами по формату v1. Группировка не должна делать точный ключ недоступным для поиска; не вводить новый kind без согласования формата.
3. Разделить ключ, значение перевода, поисковый alias и поле модели. Один текст у нескольких ключей должен давать различимые результаты, а не общую сущность без владельца.
4. Сопоставить localize/format и HBS localize/formGroup/label из уже расширенных областей; статический ключ связывать прямо, динамический label/интерполяцию оставлять условием/границей.
5. Показать подключение en/ru в манифесте и внешний lookup/fallback Foundry. Сравнить отсутствующие ключи и placeholders с R016-20/21/22; чтение JSON не равно запуску браузера.
6. Добавить компактный процесс выбора ключа/подписи до внешнего разрешения и использования результата; не выдумывать локальный алгоритм ядра и новые локальные шаги ради количественного охвата.
7. В конце сверить накопленную очередь .006–.011: прямые и обратные зависимости новых областей, участие полей/методов в процессах, актуальность и все IQ-01–IQ-08. Зафиксировать следующий остаток без автоматического создания новых TASK.

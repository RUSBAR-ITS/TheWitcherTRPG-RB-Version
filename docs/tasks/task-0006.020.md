## Порядок работы

1. Связать registration → callback → selector/dataset → документ/метод; наличие callback в коде не считать подтверждением его вызова во всех версиях Foundry.
2. Для конкретных отправителей addItem/эффектов/надёжности сопоставить аргументы и получателей query/socket; не строить фиктивную общую сетевую цепочку для всех действий боя.
3. Показать проверку activeGM, неразрешённый UUID/отсутствие Actor, неизвестный метод и возврат true/false; return из dispatcher не означает сохранение результата.
4. Довести updateCombat до реальной передаваемой формы аргумента, выбора combatant и периодического damage; сохранив барьеры из аудита, не обходить их выдуманным runtime.
5. Передать regeneration/heal в .022, crit actions в .021; точные интерфейсы связать с существующими процессами .006/.008.

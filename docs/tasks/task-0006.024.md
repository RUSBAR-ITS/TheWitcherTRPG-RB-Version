## Порядок работы

1. Составить по обоим sidebar перечень ресурсных полей: определение → control → обработчик/унаследованный submit → payload → подготовка. Явно различить value, max, unmodifiedMax и временное представление.
2. Проследить _onRecoverSta в текущем и прежнем листе: кнопки, REC.value, ввод пользователя, обновление и сообщения. Переиспользовать уже описанные luck/adrenaline/death действия.
3. Проверить конкретный контракт Foundry submitOnChange, типизацию ввода и запуск подготовки после обновления. Привести прочитанный участок/версию; недоказанную запись обозначить внешней границей.
4. Дополнить обратный поиск HP/STA/vigor и прочих реально найденных ресурсных полей ручными входами; сравнить с writers урона, consume, отдыха и Combat. Не выводить writer только из наличия HTML name.

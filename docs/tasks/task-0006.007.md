## Результат

По действию мастера, пути изменяемого поля или системному флагу находить PARTS/контекст, поставщика подсказок, callback и update-payload, затем переходить к уже внесённым _preCreate/_preUpdate и процессу назначения фазы.

Итог этой задачи — записи справочника и проверяемые примеры поиска. Исходники в таблицах используются для чтения. Игровое поведение, документы мира и содержимое компедиумов не изменяются.

## Порядок работы

Применяются [общие требования расширения](task-0006-system-index.md#общие-требования-к-расширению-006011), формат v1 и существующие постоянные ID.

1. Связать зарегистрированный класс листа с DEFAULT_OPTIONS.actions.wizard, создаваемой кнопкой, PARTS и TABS; различить путь ресурса ядра и локальный system-specific.
2. Сопоставить каждую группу подсказок с возвращаемыми путями и реальным потребителем changes. Объявленное предложение пути не доказывает числового изменения соответствующей модели.
3. Проследить wizardAction: выбор типа → получение selects → renderTemplate → prompt → split пути → добавление в prepared changes → запрос update. Зафиксировать реально ожидаемые и не ожидаемые операции.
4. Показать различие текущей формы, prepared и _source. Связать частичный payload после внешнего cleanData с proc-000007/_preUpdate; не дублировать существующий процесс.
5. Отдельно описать autocomplete и выбор @skill при создании: конкретные источники списка, отмена и unresolved target. Проверить late refs issue-00043 и смежных issues.
6. В конце сверить JS → HBS → CSS → callback → payload → поле; отмечать отсутствующую сторону связи явно, без автоматического исправления системы.

## Проблема и результат

Для исследования системы нужен полный перечень файлов в согласованных границах, позволяющий проверить охват и найти описание каждого включённого файла. Результат этапа — зафиксированный состав исследуемого среза, общий реестр, единый шаблон карточки и журнал перекрёстных проверок.

На указанном при постановке коммите отслеживается 701 файл. После применения согласованных исключений 80 файлов исключаются, 621 файл остаётся для исследования. Этот подсчёт проверен 2026-09-10 и не заменяет инвентаризацию: при выполнении нужно сопоставить перечень с фактическим деревом и учесть относящиеся к исследованию незакоммиченные и игнорируемые файлы. Число 621 — результат проверки данного среза, а не постоянный норматив.

## Требования

- В реестре одна строка на каждый файл исследуемого среза. Обязательные столбцы: полный относительный путь, краткое назначение, ссылка на подробное описание, статус анализа.
- Учитывать `module/`, `templates/`, CSS из `styles/`, `lang/`, `packsJson/`, `utils/`, а также `system.json`, `package.json` и `build.json`.
- Применять согласованный ниже список исключений. Исключённые файлы не получают строк реестра и отдельных карточек; сведения о границах исследования сохраняются в его README.
- Сравнить Git-перечень с фактическим деревом с учётом этих исключений. Для остальных игнорируемых и неотслеживаемых файлов установить роль и отметить наличие; дополнительные исключения согласовывать, не выводя их автоматически из `.gitignore`.
- Зафиксировать дату, ветку, полный хеш коммита и относящиеся к исследованию незакоммиченные изменения. Для файлов вне коммита указать, как зафиксирована их версия.
- Сохранить расширение исходного файла в имени карточки и повторять его путь под каталогом `files`: например, `module/TheWitcherTRPG.js` → `files/module/TheWitcherTRPG.js.md`.
- Не выдавать перечень путей за завершённый анализ. До чтения файла его назначение отмечается как не установленное, подробное описание — как не подготовленное. Ссылку добавлять только на существующую карточку.
- Для карточек согласован единый состав: назначение; функции и методы с входами и результатами; введённые сущности и действия с ними; зависимости; известные потребители; условия вызова и изменения данных; доказательства и пределы проверки; связанные проблемы.
- Таблица зависимостей содержит используемую сущность, файл-источник или внешний API, вид связи, место и цель использования, основание вывода.
- Учитывать не только импорты: регистрации, наследование, вызовы через `Hooks`, глобальные объекты, настройки, шаблоны, ресурсы и динамические обращения. Неустановленную связь помечать явно.
- Для неисполняемых файлов адаптировать карточку к их содержимому; отсутствие функций указывать прямо.
- Найденные проблемы регистрировать в `docs/issues/potential` по [правилам](../rules/issues.md). Пользователь разрешил их регистрацию в ходе этого исследования; подтверждение и исправление согласовываются отдельно.

## Согласованные исключения

Пользователь согласовал перечень 2026-09-10. Все пути указаны относительно корня репозитория. Каталоги исключаются целиком, включая вложенные файлы. Шаблон `packs/**/LOCK` исключает только файлы с именем `LOCK` внутри `packs/`.

| Путь | Причина исключения |
| --- | --- |
| `docs/` | Вся документация проекта, включая результаты этого исследования |
| `assets/` | Изображения; в проверенном срезе 36 PNG и 3 SVG |
| `.github/` | Шаблоны GitHub и автоматизация |
| `.git/` | Служебные данные Git |
| `README.md` | Вводная документация |
| `AGENTS.md` | Инструкции работы с репозиторием |
| `LICENSE` | Текст лицензии |
| `.gitignore` | Правила исключения файлов из Git |
| `.prettierrc` | Настройки форматирования |
| `.prettierignore` | Исключения для форматирования |
| `jsconfig.json.default` | Шаблон конфигурации среды разработки |
| `package-lock.json` | Автоматически сформированный перечень зафиксированных npm-зависимостей |
| `styles/fonts/thewitcher2.ttf` | Файл шрифта |
| `packs/**/LOCK` | Служебные файлы блокировки; сейчас пять пустых файлов |

Исключение относится к пофайловому реестру и отдельным описаниям, но не запрещает использовать файл как справочный источник. `AGENTS.md` продолжает определять правила работы; `package-lock.json` при необходимости используется для уточнения версий зависимостей. Ссылки из исследуемого кода на исключённые ресурсы можно фиксировать в карточке использующего их файла, явно указывая, что ресурс находится вне границ пофайлового анализа.

`packsJson/` остаётся в исследовании как содержимое компедиумов. Для `packs/` согласовано исключение файлов `LOCK`, а не всего каталога. Наличие ссылки на исключённый файл не включает его обратно в реестр автоматически.

При создании `docs/analytics/code-audit/README.md` перенести туда этот перечень, причины и правила его применения. Вся папка `docs/` остаётся вне исследуемого состава, хотя именно в ней создаются результаты работы.

## Порядок выполнения

1. Проверить ветку и рабочее дерево, зафиксировать исходный срез.
2. Получить перечень отслеживаемых файлов, применить согласованные исключения и сопоставить оставшийся состав с фактическим деревом, включая скрытые и игнорируемые файлы вне исключённых путей. Не запускать сборку или извлечение компедиумов для составления перечня.
3. Записать включённые категории и перенести согласованный список исключений в README исследования; объяснить расхождения между Git и файловой системой.
4. Создать основу исследования, шаблон карточки и реестр всех включённых файлов.
5. Записать порядок обновления реестра и карточек: изменение исследованного файла требует пересмотра относящихся к нему выводов; новая версия не подменяет исходный срез незаметно.
6. Выполнить перекрёстную сверку и сохранить её результат в журнале.

## Границы

Этап создаёт основу исследования и проверяет полноту списка после согласованных исключений. Глубокое описание поведения файлов выполняется начиная с TASK-0002. Существующая документация используется только как справочный материал для сверки с текущим кодом; она не включается в пофайловый разбор и не служит доказательством поведения системы.

Граф зависимостей и полные описания процессов будут строиться позднее. Сейчас фиксируются необходимые для них сущности и связи.

## Аналитика и решение

Место хранения результатов: `docs/analytics/code-audit`. Методика и границы исследования описываются в его README. Основной реестр и карточки хранятся в одном согласованном месте; журнал проверок содержит ссылки на проверенные материалы.

[Состояние репозитория](../analytics/repository-baseline.md) — справочный документ, который необходимо соотнести с фактической версией при выполнении. Его дата и коммит не заменяют фиксацию нового исследуемого среза.

## Критерии приёмки

- [ ] Указаны дата, ветка, коммит и изменения рабочего дерева, существенные для исследования.
- [ ] Git-перечень сопоставлен с фактическими файлами; расхождения и исключения объяснены.
- [ ] Согласованный список исключений с причинами и правилами применения перенесён в README исследования.
- [ ] Исключённые файлы отсутствуют в строках реестра и среди отдельных карточек; справочное использование не меняет их статус.
- [ ] Каждому включённому файлу соответствует ровно одна строка реестра.
- [ ] В реестре нет дубликатов путей и ссылок на отсутствующие карточки.
- [ ] Незавершённые описания явно отличимы от проверенных.
- [ ] Шаблон охватывает согласованные разделы и таблицу зависимостей.
- [ ] В журнале записана перекрёстная сверка полноты, ссылок и исходной версии.
- [ ] Обнаруженные проблемы оформлены в `potential` без автоматического подтверждения или исправления.
- [ ] Навигация, задача и CHANGELOG соответствуют выполненной работе.

## Проверки

Запланированы: сравнение множества файлов исследуемого среза после исключений с множеством путей реестра в обе стороны; отдельная проверка отсутствия исключённых файлов в реестре и среди карточек; проверка уникальности строк, существования исходников и карточек, корректности локальных ссылок и Markdown; повторная проверка Git-состояния на предмет изменения исходников во время этапа.

Количество файлов сверяется вместе с самими путями: совпадение чисел не доказывает полноту. Итоги команд и ограничения записать в журнале, не заменяя результат перечнем намерений.

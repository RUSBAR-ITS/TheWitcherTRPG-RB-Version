## Порядок разбора

1. Разобрать все три экспорта и создаваемые поля: типы, defaults, callback randomID и независимость наборов полей.
2. Проверить прямые/динамические импорты, сборку схем, регистрацию и употребления имён в исследуемом срезе; указать границы поиска.
3. Сопоставить фабрики с действующей моделью ActiveEffect, changes и мастерским интерфейсом: наличие одинакового слова modifier не доказывает общей схемы или исполнения.
4. Установить, где выполняются валидация, арифметика и ограничения, если потребители найдены; при их отсутствии не приписывать эти действия фабрикам.
5. Для семи CSS перечислить все селекторы/правила по смысловым группам, вложенность, состояния и анимации; найти HTML и JS, формирующие нужные классы.
6. Сопоставить current/legacy редакторы, список эффектов и вкладки Actor с фактическими селекторами; не выводить назначение CSS из имени каталога.
7. Проверить порядок @import, пересечения с базовыми стилями и другими файлами; сохранить отдельные таблицы зависимостей для каждого CSS.

## Проверки

- Создание свежих полей, генерация ID, различия пустого modifier и строки 0; настоящий тип StringField и отсутствующие ограничения.
- Наличие определений и потребителей с учётом исходных путей, ссылок/регистрации и экспорта; отрицательный результат поиска ограничить текущим репозиторием.
- Отделить доступность файла, возможность прямого импорта, регистрацию модели и фактический вызов. Не считать отсутствие подключения само по себе зарегистрированной проблемой.
- У всех семи CSS проверены селекторы, вложенность, псевдоклассы, состояния и @keyframes; области current/legacy разметки различены.
- При отсутствии совпадений указать область поиска и динамические классы; статическая сверка CSS не считается визуальным тестом браузера.

После содержательного разбора сверить карточки с исходниками, определения и потребителей — между собой, реестр — с точным составом порции. Проверки должны устанавливать наблюдаемый результат; ожидаемое значение не вычислять проверяемой функцией.

Для CSS перечислять все селекторы и существенные группы declarations, подключения, классы-потребители и пересечения каскада. Отсутствие функций не освобождает от описания сущностей и зависимостей. Совпадение селектора, доступность ресурса и фактическую отрисовку различать.

При использовании Foundry фиксировать фактическую версию и источник. Различать настоящий код, локальные фасады, браузер и серверную запись. Проверять очистку DataModel на границе производителя и потребителя; запрос update не объявлять сохранённым результатом. Если ранняя ошибка блокирует маршрут, явно ограничить отдельную проверку следующей стадии. Для переводов учитывать штатные expandObject и fallback.

Создание стенда, сборка, изменение исходников/игровых данных и исправление выявленных проблем не входят в задачу. Полный игровой процесс не считается проверенным по статическому чтению или подменённым API.

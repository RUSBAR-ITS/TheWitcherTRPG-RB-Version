## Порядок работы

1. Проверить критерии .001–.017 и соответствие их результатов общим матрицам. Новые изменения исходников или docs не скрывать обновлением даты старого вывода.
2. Сопоставить обе стороны каждой зарегистрированной связи: определение/экспорт/реестр/поле → место использования → конечное действие. При расхождении вернуться к исходному коду и уточнить обе карточки.
3. Проверить процессы, пересекающие несколько блоков: эффект → характеристика → бросок; форма Item → применение → сообщение → Actor; атака → защита → урон → травма → лечение; магия → область → удалённое действие; экономика → Item/валюта → чат; таблица → рекурсия → конечный потребитель.
4. Проверить все строки issues и результаты назначенных предметных блоков. Полностью перечитать изменившиеся/спорные карточки и их уточнения; для необработанного issue выполнить содержательную сверку, а не только проверку существования ссылки.
5. Составить отношения проблем: одна причина/возможный дубль, разные причины одного симптома, последовательные барьеры одного процесса, независимые наблюдения. Проверить известный 00029/00200; не удалять, не объединять и не закрывать документы без пользовательского решения.
6. Сопоставить ранние ошибки с поздними проверками. Если нижняя ветвь достигнута только диагностическим входом/фасадом, не описывать её как доказанное прохождение обычного пользовательского процесса.
7. Закрыть адресацию всех «проверить позднее»: либо записать результат с доказательством, либо точную недоступную/неразрешённую границу и её влияние на итог. Незавершённую доступную проверку не маскировать общей оговоркой.
8. Проверить относительные ссылки, якоря, форматы таблиц, актуальные счётчики и статусы. Сохранить исторические документы и показатели срезов; текущие вводные синхронизировать отдельно.
9. Завершить протокол cross-check-0002 и запись TASK-0004.018 в журнале. TASK-0004 перевести в done только после фактического выполнения критериев родителя; перечислить материалы для TASK-0005 и её остающийся draft.

## Итоговые матрицы

Использовать [формат родителя](task-0004-cross-checks.md#формат-материалов). Для каждого файла — основной блок/результат/основание; для связи — оба конца, условие, действие и доказательство; для issue — технический результат сверки отдельно от пользовательского статуса; для оставшегося вопроса — точная граница и достаточная следующая проверка.

Не создавать число независимых дефектов вычитанием всех похожих названий. Совпадение текста двух карточек не доказывает совпадение причины. Структурная проверка полноты TASK-0004 служит контролем её материалов и не заменяет независимый финальный этап TASK-0005.

# Задачи и технические задания

## Пофайловое исследование системы

Пользователь согласовал пофайловый анализ текущей системы, единый реестр файлов, подробные карточки сущностей и зависимостей, работу порциями и перекрёстную сверку после каждого этапа.

**Все результаты исследования хранятся в [docs/analytics/code-audit](../analytics/code-audit/README.md).** Созданы [реестр](../analytics/code-audit/registry.md), [журнал сверок](../analytics/code-audit/review-log.md), [шаблон карточки](../analytics/code-audit/templates/file.md) и [каталог карточек](../analytics/code-audit/files/README.md). Пофайловое описание назначения и связей начинается со следующего этапа.

Из пофайлового реестра и отдельных описаний исключены каталоги `docs/`, `assets/`, `.github/`, `.git/` целиком и служебные файлы по [согласованному перечню](../analytics/code-audit/README.md#согласованные-исключения). Исключённые файлы могут использоваться как справочные источники. В зафиксированном при инвентаризации коммите отслеживается 706 файлов: 85 исключены, 621 включён в реестр. Перечень и правила применения перенесены в README исследования.

| ID | Задача | Статус | Зависимости и место в работе |
| --- | --- | --- | --- |
| [TASK-0001](task-0001-code-inventory.md) | Инвентаризация файлов и основа анализа | `done` | Реестр 621 файла создан, состав и ссылки проверены |
| [TASK-0002](task-0002-system-initialization.md) | Манифест, точка входа и регистрация компонентов | `planned` | После TASK-0001 |
| [TASK-0003](task-0003-remaining-files.md) | Порционный разбор остальных файлов | `draft` | Детализируется после первых двух этапов |
| [TASK-0004](task-0004-cross-checks.md) | Сквозная сверка описаний и зависимостей | `draft` | По мере появления порций; обязательные сверки первых двух этапов уже включены в их критерии |
| [TASK-0005](task-0005-final-coverage.md) | Итоговая проверка полноты | `draft` | После разбора файлов и сквозной сверки |

TASK-0001 завершена. TASK-0002 оформлена подробно и ожидает выполнения. Остальные задачи — заготовки: их перечни файлов, проверки и подзадачи будут согласовываться по результатам анализа. Подробных карточек исходных файлов пока нет; составление реестра не означает завершения исследования.

Найденные при этом исследовании проблемы разрешено регистрировать в `docs/issues/potential` по [правилам](../rules/issues.md). Это не подтверждение проблемы и не разрешение исправлять систему.

## Ведение задач

Задачи формируются с пользователем. Наблюдения в аналитике не становятся задачами автоматически. После создания ID и путь документа сохраняются при изменении статуса; ID не переиспользуются.

Для оформления используется [общий шаблон](templates/task.md). Сам шаблон не является задачей.

Порядок согласования и ведения документов описан в [правилах документации](../rules/documentation.md).

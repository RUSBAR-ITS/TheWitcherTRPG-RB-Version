## Сбой Б10: первое назначение из двух клиентов

1. У тестового Actor `zpCrKO4pWaUOIku0` нет травм, QA-GM и QA-Player имеют право изменения. Шаблон виден обоим клиентам.
2. Два независимых браузерных контекста в согласованный момент вызывают настоящий installWound для `woundTypeId=qa-family`, `location=torso`. Сетевые/документные методы в этом сценарии не подменялись.
3. QA-GM: applied, Item `0bYZmHcKo4ObV0Vj`. QA-Player: failed/uncertainWrite, Item `S67eZyRfpZduatPn`. Обе записи уже присутствуют на Actor; ошибка второго вызова не откатывает созданный Item.
4. После reload обеих страниц те же два ID присутствуют у обоих клиентов. Это серверное сохранение, не расхождение локального кеша.

Причина соответствует границе кода: [withWoundQueue](../../module/item/criticalWoundOperations.js) сериализует операции только внутри одного клиента. Оба клиента успевают увидеть отсутствие совпадения до native create; проверка после записи обнаруживает неоднозначность слишком поздно. Дополнительный тест одновременно изменяемой существующей стадии после найденного сбоя не расширялся.

**Последующее решение пользователя, .00051:** случай принят как [ограничение одновременного назначения](../documentation/known-limitations.md#wound-concurrency); дополнительную защиту не внедряем. Новая issue/подзадача не создаётся. Результат Б10 остаётся воспроизведённым ограничением, а не успешно пройденной проверкой межклиентной уникальности.

## Сохранение, диагностика и уборка

Пять HTTP-ресурсов (операции, WitcherItem, модель, JS/HBS конфигурации) совпали с файлами репозитория. После reload игровые данные трёх Actor совпали: при сравнении исключены только серверные `_stats` и добавляемые при загрузке `system.skills.*.*.label`; все остальные поля, Item и ActiveEffect сравнивались. Исходная побайтная/JSON.stringify проверка без этих различий отмечена как неудачный критерий стенда, не как пропажа травм.

Диагностические снимки доставлены на диск: исходный `0cf7ddbb-4bdf-4113-8f8b-98411edaeb1e`, основной результат `e5d69453-f8bf-4d57-8d7b-621576bad31e`, гонка `4d7e1980-4b4a-4d33-ae9f-590a00ab70a7`, гонка после reload `f731213f-9dca-4e6c-b23a-8b19553a63c1`. Непрерывный журнал не объявляется полным: после reload ключ коллектора нужно снова передать клиенту; до этого зафиксированы ошибки доставки. Canvas ticker временно остановлен только в двух headless-клиентах, не на сервере.

Удалены строго свои 3 Actor со вложенными Item/эффектами, 3 мировых шаблона, 3 временные библиотеки и 18 помеченных сообщений. Исходные два сообщения, сцена, две папки и остальные исходные коллекции сохранены. Настройка criticalWoundsPack возвращена к системной, язык ru, клиентское логирование возвращено в исходное false. Повторный reload обеих страниц подтвердил отсутствие fixtures и готовность мира. Браузер закрыт; права файлов, служба Foundry и игровой код не менялись.

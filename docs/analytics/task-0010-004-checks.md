## Реализация и пределы

`parameterCalculation.js` — независимый численный расчёт: сложение, умножение, затем замена с высшим приоритетом (при равенстве — последняя в исходном стабильном порядке). Округление вниз один раз в конце результата, после него границы. Отдельные value/cap/advancement/fullExtra/rollModifier/rollExtra/optionalChanges. Сдвиг потолка использует ту же арифметику; при минимуме1 отрицательный потолок не отменяет минимум. Для навыков нижняя граница отсутствует, для текущих ресурсов универсального потолка10 нет.

Полный остаток определяется сравнением общего результата с расчётом только обычных строк: ограниченный обычный вклад плюс разница необрезанных результатов. Поэтому обычный бонус не становится полным из-за соседней строки; согласованный9 + обычные2 + полные2 даёт value10/rollExtra2 независимо от порядка этих двух строк. Чистый вычислитель не читает Documents, не выполняет бросок и не изменяет вход.

`parameterPreparation.js` связывает расчёт с Actor. WeakMap хранит входы в пределах подготовки; prepareBaseData сбрасывает только временное состояние. allApplicableEffects и effect.active сохраняют штатный отбор собственных и переносимых эффектов, disabled/suppression/экипировку. Каждая строка хранит source UUID/name/index/phase и настройки, выражение разрешается native NumberField/Roll без промежуточного целочисленного округления. Неверное выражение даёт штатное предупреждение и пропуск строки, а не нулевой множитель. Последующие локальные расчёты используют уже разрешённые значения.

В .004 подключены основные характеристики, максимумы Удачи/Токсичности и встроенные навыки. Numeric ADD/MULTIPLY/OVERRIDE initial/final собираются до зависимых вычислений, а shouldApplyChange исключает их повторное применение ядром. Фазы ядра выполняются по одному разу; статусы и token changes проходят штатно. Registered handlers, CUSTOM/upgrade/downgrade, нечисловые/специальные Item-операции и пока не подключённые цели остаются native. `luck.value`/`toxicity.value` — текущие запасы, в эту маршрутизацию не входят.

В WitcherActor удалён второй calculateStats. Сначала вычисляются максимумы без контекстных штрафов, затем существующие состояния здоровья/перегруз/броня как отдельные входы действующего значения. Перегруз вычитается один раз из REF/DEX/SPD; EV отдельно из REF/DEX. После пересчёта BODY.max уже включает модификаторы — при расчёте грузоподъёмности они второй раз не прибавляются. Локальный повтор не накапливает luck/toxicity; текущие запасы не пополняются и не обрезаются в prepare.

Встроенный Skill сохраняет базовый value для существующих потребителей; activeEffectModifiers представляет разницу между результатом и этой базой. Значение modifiedValue может быть отрицательным. Итоговые каналы/входы доступны в transient `actor.parameterModifiers` (Map с ключами вида system.stats.body/system.skills.dex.archery), вне `_source` и обновлений БД.

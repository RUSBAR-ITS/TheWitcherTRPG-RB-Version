## Назначение и границы

Справочник помогает по понятию, имени, пути файла или поля находить соответствующий код, его связи и место в существующих процессах. Результат поиска — небольшой связанный набор адресов и пояснений, из которого можно перейти к подробному описанию.

Источники — [реестр](code-audit/registry.md), [615 карточек файлов](code-audit/files/README.md), [матрицы и процессы](code-audit/cross-check-0002.md#результаты-task-0004018), [протоколы](code-audit/review-log.md) и [issues](../issues/README.md). Фактические определения и связи сверяются с текущими исходниками. Подробные объяснения и исторические доказательства остаются в существующих материалах; индекс хранит их адреса и краткие сведения для навигации.

Границы исходников соответствуют [охвату аудита](code-audit/README.md#согласованные-исключения): движок, en/ru и экспортные JSON компедиумов. Внешние API и динамические цели показываются как границы связей. Содержание живого мира и исключённые файлы не становятся исследованными из-за наличия ссылки на них.

Справочник описывает существующее устройство. Цели будущих изменений, выбор новой механики, согласование реализации и план разработки в его содержание не входят.

## Справочные запросы

| ID | Запрос | Необходимый результат |
| --- | --- | --- |
| <a id="iq-01"></a>IQ-01 | Где реализовано понятие или механизм? | Подходящие сущности и файлы, точные имена и краткие роли. Поиск по русскому/английскому термину, символу, ключу или пути; неоднозначные совпадения различаются по контексту. |
| <a id="iq-02"></a>IQ-02 | Где определена сущность? | Файл, класс/метод/поле либо место регистрации, владелец определения и ссылка на подробную карточку. Унаследованное определение отличимо от локального. |
| <a id="iq-03"></a>IQ-03 | Как она подключается или вызывается? | Регистрация, доступные точки входа и условия вызова: импорт, действие интерфейса, событие, прямой вызов или этап жизненного цикла. |
| <a id="iq-04"></a>IQ-04 | Что она использует? | Исходящие связи: адресат, вид использования, место обращения и существенное условие. |
| <a id="iq-05"></a>IQ-05 | Кто использует её? | Входящие связи с конкретными потребителями и местами использования. Для косвенного потребителя — цепочка переходов. |
| <a id="iq-06"></a>IQ-06 | Кто читает, вычисляет и изменяет поле? | Определение поля, читатели/писатели, вычисления и копирование; различие исходного, подготовленного и сохраняемого значения, где оно установлено. |
| <a id="iq-07"></a>IQ-07 | В каких процессах она участвует? | Ссылки на процессы, входы, шаги и переходы с условиями; роль сущности и место в последовательности действий. |
| <a id="iq-08"></a>IQ-08 | Где находятся подробности, доказательства и известные ограничения? | Карточка, конкретные разделы аудита и связанные issues; версия, вид доказательства и явно отмеченные неразрешённые связи. |

Это запросы агента к справочнику. Для их выполнения используются существующие сведения о системе.

## Минимальная логическая структура

Нужны записи о сущностях, связях и процессах. Ниже определено их содержание; физический формат, разбиение файлов и программный интерфейс поиска пока не выбираются.

### Сущность

| Реквизит | Содержание |
| --- | --- |
| ID | Однозначная ссылка внутри индекса; номер строки не является идентификатором |
| Вид и имя | Файл, класс, функция/метод, поле модели, обработчик/событие, настройка, шаблон или значимый документ данных; точное имя из источника |
| Поисковые обозначения | Термины и подписи en/ru, ключи, квалифицированное имя или UUID, по которым сущность действительно можно найти |
| Определение и контекст | Относительный путь, точный символ/ключ и место определения; владелец, модель или тип документа, когда это нужно для различения |
| Краткое назначение | Одно-два предложения о существующей роли |
| Ссылки | Подробная карточка/раздел описания и относящиеся issues |
| Актуальность | Проверенная версия определения и основание краткого описания |

Одинаковые имена в разных классах, путях или моделях не объединяются автоматически. Содержательная сущность может включать группу однотипных данных; отдельный узел для каждого локального значения или ключа JSON не требуется. Детализация должна позволять указать точного участника каждой зарегистрированной связи.

### Связь

| Реквизит | Содержание |
| --- | --- |
| ID и концы | Однозначная ссылка на связь, ID источника и цели |
| Вид | Определённый тип отношения из таблицы ниже |
| Место использования | Файл и конкретный вызов, обращение, регистрация, ключ либо выражение |
| Условия и контекст | Тип документа, ветвь, фаза и другие установленные ограничения применимости |
| Передаваемые данные | Существенный аргумент, поле или путь данных, если без него нельзя понять связь |
| Основание и актуальность | Ссылка на исходник/доказательство и проверенная версия |
| Разрешимость | Конкретная цель либо явное динамическое выражение/внешняя граница с указанием неизвестного |

Обратный поиск использует те же связи с перестановкой направления обхода. Отдельная вручную поддерживаемая копия списка потребителей не нужна. Несколько мест использования одной пары сущностей сохраняются, если различаются условия, данные или смысл обращения.

Минимально различимые отношения:

| Отношение | Направление и смысл |
| --- | --- |
| Содержит/определяет | Файл или владелец → объявленная сущность |
| Импортирует | Импортирующий файл → источник импорта; импорт не означает вызов всех функций файла |
| Наследует/подключает реализацию | Класс → базовый класс или mixin с указанием способа подключения |
| Регистрирует | Код регистрации → зарегистрированная сущность и ключ реестра |
| Вызывает | Вызывающая сущность → вызываемая функция/метод |
| Читает | Читатель → поле/настройка/данные |
| Вычисляет/записывает | Вычисляющая или записывающая сущность → поле; вид операции сохраняется |
| Передаёт данные | Производитель → потребитель с указанием передаваемого значения и места передачи |
| Отправляет событие/запрос | Отправитель → событие или канал/метод запроса |
| Обрабатывается | Событие/запрос → обработчик; регистрация обработчика фиксируется отдельно |
| Отображает | Код подготовки/вывода → шаблон или представление, с указанием данных при необходимости |
| Ссылается на документ | Документ/потребитель → цель ID/UUID; хранение ссылки и её фактическое разрешение различаются |

Сходство названий и упоминание в тексте не создают доказанной связи вызова. Динамический адресат не подменяется предположительно подходящей функцией. Для внешней цели достаточно адресуемой записи о границе; полный индекс исходников Foundry этим не подразумевается.

### Процесс

| Реквизит | Содержание |
| --- | --- |
| ID и название | Идентификатор процесса и краткое описание существующего действия |
| Входы | Сущности, события или этапы жизненного цикла, которые запускают процесс; существенные условия |
| Шаги | Собственные ID шагов и ссылки на выполняемые сущности; одна функция может участвовать в нескольких шагах |
| Переходы | Следующий шаг/выход, условие ветви, повтор или раннее завершение |
| Порядок исполнения | Установленные фазы, синхронный переход, ожидаемая операция, запуск без ожидания либо неизвестная граница |
| Данные и результаты | Существенные входы, чтение/запись через ссылки на связи, возврат, сообщение или запрос сохранения |
| Подробности | Разделы существующего описания процесса, доказательства и ограничения |
| Актуальность | Проверенная версия участвующих исходников и внешнего контракта, если он существенен |

Запись процесса содержит компактную структуру шагов и переходов. Развёрнутый разбор остаётся по ссылке. Зарегистрированный обработчик, действительно достигнутый шаг и диагностический вход различаются. Возврат из функции, отправка запроса и сохранённое состояние обозначаются согласно имеющимся доказательствам.

### Общие сведения о срезе и охвате

Справочник должен указывать исходный реестр, исследуемую версию, покрытые файлы/сущности/процессы и известные пропуски. Версии определений и связей должны позволять обнаружить устаревшую запись после изменения источника. Историческая проверка сохраняет свою дату и условия.

Отсутствие результата поиска различает три случая: в обработанном охвате связь не найдена; участок ещё не индексирован; цель не разрешена. Совпадение количества файлов с реестром само по себе не доказывает полноты связей.

## Форма ответа справочника

По запросу возвращаются:

1. Совпавшие сущности с ID, краткой ролью и адресом определения.
2. Запрошенные входящие/исходящие связи, сгруппированные по смыслу.
3. Связанные процессы и конкретные шаги, если они нужны для запроса.
4. Ссылки на подробные карточки, исходники, issues и доказательства.
5. Границы результата: срез, область поиска и неразрешённые участки.

Начальная выдача содержит ближайшее окружение. Дальнейший обход раскрывается по запросу; косвенная связь сопровождается цепочкой, а не только именем конечного файла. Точный поиск по символу/пути должен оставаться доступным наряду с поиском по терминам.

Например, запрос activeEffectModifiers должен позволять найти все подходящие определения с их владельцами, затем отдельно получить читателей, писателей и процессы использования. Полные расчёты, история проверок и описание известных проблем доступны по ссылкам. Это пример требуемого поиска, а не уже полученный результат индекса.

## Проверка пригодности справочника

- Все восемь запросов проверяются на конкретных сущностях текущего кода; ожидаемые существенные определения и связи устанавливаются по исходникам.
- ID однозначны, ссылки разрешаются, входящие и исходящие представления одной связи согласованы.
- Различены одноимённые сущности, условия вызова и виды отношений; текстовое совпадение не выдаётся за исполняемую связь.
- Переходы процесса ссылаются на реальные участки кода; порядок и достижимость не выводятся только из списка зависимостей.
- Ссылки ведут к актуальным уточнениям; неизвестные и устаревшие сведения явно видны.
- Поиск даёт достаточно адресов для понимания участка, сохраняя возможность углубиться в подробности без загрузки всего корпуса.

Графические схемы могут представлять эти же записи. Их читаемость полезна, но основная проверка — возможность быстро и точно находить определения, связи, процессы и источники сведений о текущей системе.

## Что реализовано

Формулы отделены от нативных фаз и собственных модификаторов производной. calculateDerivedParameter получает формулу либо ручную базу, затем применяет собственные строки через общий вычислитель. Поддержанные initial/final-строки больше не перезаписываются формулой и не применяются ядром второй раз. Нет проверки имени/ID травмы. Числовое исправление issue-00036 реализовано; статус issue сохраняется до игровой приёмки и подтверждения пользователя.

Для каждой зависимости заново рассчитывается основной параметр без исключённых строк. Контекст здоровья/EV/перегруза сохранён отдельно; фильтрация одной строки не выключает соседнюю строку того же эффекта. Run получает SPD; Leap — результат Run с учётом исключений на обоих рёбрах. BODY-урон использует отдельный адрес исключения для meleeBonus/punch/kick. Заживление по-прежнему читает действующее BODY через evaluateHealingDuration.

Среднее BODY/WILL не округляется до умножения на5: HP/STA округляются после собственной арифметики. Resolve/Focus также используют конечное округление параметра. Порог ранения и ёмкость, определяющая перегруз, сохраняют назначение входов без контекстного штрафа здоровья: порог не запускает обратную зависимость через собственное снижение WILL. Для остальных значений используются действующие входы; первичный максимум и значение фиксированной производной сохраняют назначение прежних полей. STUN ограничивается1–10 после собственной арифметики; универсальный потолок10 ресурсам не добавлен.

Ручной режим монстра работает для HP/STA/Resolve/Focus; Vigor/Shield всегда сохраняют ручную базу. Общий isManualDerivedStat используется моделью, расчётом и редактором. Сохранённая база не заменяется подготовленной формулой. Значения текущих ресурсов остаются нативными входами, не модификаторами ёмкости. Подготовка не выполняет update, не выдаёт запас при росте max и пока не сохраняет обрезание запаса при снижении max — это .006.

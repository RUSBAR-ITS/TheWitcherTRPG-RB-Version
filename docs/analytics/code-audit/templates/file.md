# Путь исходного файла

Шаблон описания, а не карточка исследованного файла. Перед использованием прочитать [порядок исследования](../README.md). Сохранить карточку под `files/` с повторением исходного пути и добавлением `.md`; относительные ссылки пересчитать из места её сохранения.

| Поле | Значение |
| --- | --- |
| Исходный файл | Полный относительный путь и ссылка на существующий исходник |
| Тип файла | JavaScript / JSON / Handlebars / CSS / другой фактический тип |
| Статус анализа | Не начат / В работе / Проверено / Требует актуализации |
| Дата проверки | ГГГГ-ММ-ДД |
| Ветка и коммит | Версия, на которой проверены выводы |
| Изменения относительно коммита | Нет / конкретные изменения; для файла вне коммита — контрольная сумма |
| Задача и порция | Ссылка на задачу и обозначение порции |
| Запись перекрёстной сверки | Ссылка на фактически выполненную проверку в журнале |

## Назначение файла

Какую ответственность несёт файл и где участвует в работе системы. Вывод обосновать содержимым и местами использования. Непрочитанные части или неустановленное назначение отметить явно.

## Условия использования

Как файл подключается или загружается; что выполняется при импорте, при событии, при действии пользователя или при вызове из другого файла. Для события разделить регистрацию обработчика и последующий вызов. Для данных и шаблонов указать условия их чтения или отображения.

## Введённые сущности и действия с ними

| Сущность | Вид и место определения | Назначение | Доступность или регистрация | Действия и жизненный цикл |
| --- | --- | --- | --- | --- |
| Точное имя из файла | Класс, функция, поле модели, настройка, объект, обработчик и т. п.; строки или раздел | Проверенное назначение | Экспорт, локальная сущность, ключ реестра и т. п. | Создание, чтение, изменение, удаление или иное фактическое действие |

Перечислить определения файла, включая существенные анонимные обработчики с указанием места регистрации. Для JSON перечислять структуру и значимые ключи или документы; для CSS — селекторы и правила по смысловым группам. Если введённых программных сущностей нет, указать это, сохранив описание содержимого соответствующего типа.

## Основные функции и методы

| Функция или метод | Входы и предусловия | Результат | Основные действия | Ошибки, асинхронность и изменения состояния |
| --- | --- | --- | --- | --- |
| Имя; для метода — класс и имя | Существенные параметры, контекст и ожидаемые данные | Возвращаемое значение или отсутствие результата | Проверенная последовательность действий | Записи в документы, события, исключения, ожидания и другие последствия |

Не выводить действия функции только из её названия. Если функций нет, так и написать. Значимые вычисления, ветвления и ограничения описать в тексте, когда таблицы недостаточно.

## Используемые сущности и зависимости

| Используемая сущность | Файл-источник или внешний API | Вид связи | Где и зачем используется | Основание |
| --- | --- | --- | --- | --- |
| Точное имя, исходное имя и псевдоним при необходимости | Относительная ссылка на файл и имя определения либо Foundry / библиотека / модуль | Импорт, вызов, наследование, регистрация, событие, чтение данных, шаблон, ресурс и т. п. | Функция, обработчик или строки; условия и цель | Место определения и обращения; выполненная проверка или явное ограничение |

Не ограничиваться `import`: учитывать доступ через реестры, `Hooks`, глобальные объекты, настройки, шаблоны, помощники, ключи локализации и динамические обращения. Для внешнего API указывать версию или источник, если они проверялись; не приписывать внешний API файлу системы.

Если источник не установлен, указать неизвестное и способ дальнейшей проверки. Для исключённого ресурса писать «вне границ пофайлового анализа»; отдельная карточка для него не создаётся.

## Известные потребители

| Файл-потребитель | Используемая сущность этого файла | Способ и условия использования | Основание |
| --- | --- | --- | --- |
| Относительная ссылка | Точное имя или ключ | Вызов, регистрация, загрузка и т. п. | Место обращения и результат сверки |

Указать область поиска потребителей. Формулировка «не найдено в проверенной области» не означает отсутствия динамических вызовов. Если соседний файл уже описан, проверить согласованность сведений в обеих карточках.

## Данные и изменения состояния

Какие данные читаются, создаются, изменяются или удаляются; какие документы, коллекции и настройки затрагиваются. Отделить расчёт в памяти от записи в Foundry, изменение интерфейса от изменения игровых данных. Для неисполняемого файла описать структуру входных данных, контекст шаблона или связь стилей с интерфейсом.

## Проверки и доказательства

| Что проверено | Источник, команда или сценарий | Фактический результат | Ограничения |
| --- | --- | --- | --- |
| Конкретное свойство или связь | Файл, сущность, строки для указанной версии; действие проверки | Полученный результат | Что этим не установлено |

Отделить статический анализ от фактического запуска. Запланированные проверки вынести в открытые вопросы. Чтение байтов, наличие импорта или совпадение контрольной суммы не подтверждают поведение функции.

## Непроверенные участки и открытые вопросы

Перечислить непрочитанные части, неустановленные динамические связи, ограничения поиска потребителей и сценарии, требующие отдельной проверки. Если вопросов нет в пределах выполненного разбора, обозначить именно эти пределы.

## Связанные проблемы

Ссылки на существующие карточки `issue-NNNNN` и краткое объяснение связи. Если при данном разборе проблем не обнаружено, указать это без вывода об исправности всей системы.

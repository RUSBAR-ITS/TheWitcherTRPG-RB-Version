## Назначение файла

Список путей, передаваемых сценарием выпуска в zip при подготовке дистрибутива системы.

## Условия использования

Реальный потребитель — [.github/workflows/get-includes.js](../../../../.github/workflows/get-includes.js): fs.readFileSync('./build.json','utf8') → JSON.parse → includes.join(" ") → console.log. [.github/workflows/release.yml](../../../../.github/workflows/release.yml) получает строку в шаге Get Includes и подставляет её в zip -r ./system.zip. Эти два исключённых файла прочитаны в пределах установления связи; карточек/покрытия им не добавлено, workflow не запускался.

## Известные потребители

Только get-includes.js непосредственно читает build.json в найденных локальных исходниках/сценариях. release.yml использует его stdout. Utils компедиумов не читают includes; Foundry загружает уже полученный пакет по system.json.

## Данные и изменения состояния

JSON не пишет данные. Выпуск отдельно запускает сборку, подставляет version/url/manifest/download в system.json, создаёт system.zip и прикрепляет архив/манифест к release. Подстановка заготовок manifest, включая исходную строку ACTIONn, предусмотрена внешним workflow; успешность выпуска здесь не проверена.

## Проверки и доказательства

Все 13 строк разобраны JSON-парсером. C06 выполнил исходный helper с фасадом readFileSync: stdout равен соединению девяти includes через пробел. Проверка существования баз шести шаблонов и трёх файлов выявила единственный отсутствующий путь ./template.json. Это не доказывает полный отказ zip: другие пути существуют, код возврата реального архиватора не измерялся.

Входная схема связей CSS/JS/языков сопоставлена с system.json и текущими каталогами. .github и README/package-lock — справочные источники вне пофайлового охвата. [Перекрёстная сверка](../review-log.md#task-0003050).

## Назначение файла

Последовательно компилирует каждый входной каталог packsJson в одноимённый LevelDB-каталог packs через Foundry CLI.

## Условия использования

[package.json](../../../../../package.json) запускает файл через npm run build:db. При импорте .mjs немедленно исполняются верхнеуровневые await и цикл; экспортов, main-guard и функции запуска нет. cwd должен указывать на корень с packsJson. Аргументы package pack не читаются. Импорт CLI должен разрешаться до начала обхода.

## Введённые сущности и действия с ними

| Сущность | Строки | Вид / действие |
| --- | --- | --- |
| compilePack | 1 | Именованный импорт внешней библиотеки |
| fs | 2 | promises из встроенного Node fs |
| MODULE_ID | 3 | process.cwd(), абсолютный рабочий каталог; вопреки имени это не ID Foundry |
| packs | 4 | Результат fs.readdir('./packsJson'): имена непосредственных записей |
| pack и верхнеуровневый цикл | 6–11 | Каждое имя, кроме ровно .gitattributes, логируется и передаётся compilePack |
| recursive:true | 10 | Рекурсивный поиск исходников внутри каждого выбранного pack библиотекой |

## Основные функции и методы

Собственных именованных функций нет; есть исполняемая верхнеуровневая последовательность.

| Операция | Вход | Результат / изменение | Ошибки и порядок |
| --- | --- | --- | --- |
| fs.readdir | ./packsJson относительно cwd | Массив имён | Отсутствие/нет доступа прекращает запуск |
| continue | pack === '.gitattributes' | Пропуск одной записи | Других фильтров нет |
| console.log | Packing + pack | Сообщение до вызова CLI | Сообщение не подтверждает успех |
| await compilePack | cwd/packsJson/pack → cwd/packs/pack, recursive:true | Promise завершения обновления одного pack | Следующий pack начинается после завершения; первый отказ прекращает цикл |

Скрипт не сортирует имена, не проверяет isDirectory и не сопоставляет их с manifest.packs. Посторонний файл readme.txt передаётся библиотеке как src и может вызвать ENOTDIR при findSourceFiles. Пустой список packsJson даёт успешное завершение без compilePack. Пустой отдельный pack при реальном CLI представляет пустой набор исходников; библиотека удаляет ключи прежней DB, которых нет в источниках.

Внешний источник API — [опубликованный пакет CLI 3.0.3](https://registry.npmjs.org/@foundryvtt/foundryvtt-cli/3.0.3), index.mjs и lib/package.mjs из tarball. Архив прочитан через HTTPS в память, SHA-512 совпал с integrity в package-lock.json; установка не выполнялась. Это проверенная версия внешнего источника, не установленная в checkout зависимость.

Контракт проверенного CLI: nedb=false/yaml=false по умолчанию; findSourceFiles выбирает только обычные файлы с расширением .json в нижнем регистре и рекурсивно обходит каталоги. Без _key документ пропускается; при повторном _key выбрасывается ошибка. compileClassicLevel создаёт dest рекурсивно, записывает primary/embedded документы через HIERARCHY, удаляет DB-ключи вне seenKeys, выполняет batch.write, compact и close. Это библиотечные действия, не собственные функции системы. Native ClassicLevel заменён фасадом; реальная DB не открывалась.

## Данные и изменения состояния

При обычном запуске обновляет packs, потенциально удаляет прежние DB-записи через CLI. Источники packsJson не переписывает. На дату проверки есть семь исходных каталогов: combat, criticalWounds, character-generator, character-generator-sub-tables, witcher-lifepath, lifepath, style. В packs найдено пять каталогов без combat/criticalWounds; содержимое баз не читалось, отсутствие не объявлено доказанным дефектом сборки.

В манифесте указан суффикс .db, однако настоящий PackageCompendiumPacks._cleanElement Foundry 14.367.0 нормализует все семь путей к каталогам без суффикса. Различие исходной строки и имени LevelDB-каталога не зарегистрировано как issue.

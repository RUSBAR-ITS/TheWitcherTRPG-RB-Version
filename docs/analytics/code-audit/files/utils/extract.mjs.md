## Назначение файла

Извлекает каталоги packs в JSON с папками компедиума, предварительно удаляя корневые JSON и очищая три имени metadata-полей.

## Условия использования

[package.json](../../../../../package.json): npm run extract. При импорте немедленно выполняются readdir и цикл с top-level await; main-guard и экспортов нет. Все относительные пути вычисляются от cwd проекта. CLI должен быть доступен; в текущем checkout он не установлен, поэтому проверялся отдельно по опубликованному исходнику с фасадами.

## Основные функции и методы

| Функция / операция | Входы | Результат и действия | Ошибки / последовательность |
| --- | --- | --- | --- |
| replacer | key и value JSON.stringify, включая вложенные объекты | Пропускает три названных ключа на любой глубине; остальные возвращает неизменными | Не ограничивается _stats; выражения и игровые поля не вычисляет |
| fs.readdir(packsCompiled) | Существующий packs | Имена, включая посторонние записи | Нет skip .gitattributes, сортировки и проверки типа |
| fs.readdir(packsJson/pack,{withFileTypes:true}) | Уже существующий выходной каталог | Dirent[] непосредственных детей | ENOENT возникает до вызова CLI и его mkdir |
| filter → map | Dirent[] | isFile и lower-case endsWith .json | Каталоги, symlink как самостоятельные Dirent и другие расширения не удаляются |
| fs.rm | Абсолютный путь одного найденного файла | Удаление без резервной копии | Ошибка может оставить частично очищенный каталог |
| await extractPack | Абсолютный packs/pack, относительный packsJson/pack | Извлечение CLI после удаления | Отказ прекращает цикл; восстановления удалённых JSON нет |

Пустой packs завершается без операций извлечения; отсутствие packs даёт ENOENT. Для каждой записи packs ожидается готовый одноимённый каталог packsJson. Все выбранные корневые JSON удаляются до попытки чтения базы CLI; вложенные папки не очищаются. Файл не оборачивает процесс в try/catch/rollback.

## Используемые сущности и зависимости

| Сущность | Источник | Вид связи и цель | Основание |
| --- | --- | --- | --- |
| extractPack | @foundryvtt/foundryvtt-cli index.mjs → lib/package.mjs | Импорт и await извлечения | Проверенный внешний исходник 3.0.3 |
| readdir, rm, Dirent.isFile | Node fs/promises | Обход/удаление, строки 7/17–21 | Исходное тело выполнено с FS в памяти |
| path.resolve; process.cwd | Node path/runtime | Пути packs/packsJson | cwd-подмена и path.resolve привязаны к виртуальному /work |
| JSON.stringify replacer | ECMAScript / внешний serializeDocument | Сериализация конечного JSON | Настоящий CLI передаёт callback в JSON.stringify |
| npm extract / CLI range | [package.json](../../../../../package.json) | Запуск и зависимость | Полный JSON проверен |
| compilePack с recursive:true | [utils/packs.mjs](../../../../../utils/packs.mjs) | Обратное чтение результата | Подбирает также оставшиеся nested JSON |
| Pack paths | [system.json](../../../../../system.json) | Набор runtime-пакетов | Имя manifest.pack не используется циклом; basename каталога используется |
| packsJson / packs | Файловые данные | Выход и вход | Проверены имена каталогов без открытия настоящих DB |

Внешний источник API — [опубликованный пакет CLI 3.0.3](https://registry.npmjs.org/@foundryvtt/foundryvtt-cli/3.0.3), index.mjs и lib/package.mjs из tarball. Архив прочитан через HTTPS в память, SHA-512 совпал с integrity в package-lock.json; установка не выполнялась. Это проверенная версия внешнего источника, не установленная в checkout зависимость.

Контракт библиотеки 3.0.3 установлен по коду, а не только JSDoc: extractPack создаёт dest и отдельный временный каталог, extractClassicLevel читает LevelDB с createIfMissing:false, folders:true строит дерево директорий по Folder. Записи Folder получают _Folder.json, прочие именованные документы — безопасное имя плюс ID; embedded-документы собираются по _key. После извлечения tmp копируется в dest. Опция clean удаляет dest лишь перед успешным копированием; наш скрипт clean не передаёт. finally удаляет tmp, но не восстанавливает ранее удалённые нашим циклом файлы.

omitVolatile не означает «удалить все volatile-поля». checkVolatile сравнивает новые данные с существующим JSON и при отличиях только пяти полей _stats (createdTime, modifiedTime, lastModifiedBy, systemVersion, coreVersion) сохраняет прежние данные для сериализации. Если прежнего файла нет, сравнение не выполняется. Затем собственный replacer удаляет три имени в любом объекте; systemVersion/coreVersion сохраняются. Значение _key сохраняется и нужно обратной сборке.

## Данные и изменения состояния

При штатном запуске удаляет и перезаписывает исходные JSON на диске, создаёт вложенные папки через CLI. Один извлечённый документ не является отдельной транзакцией с удалением старого имени. Переименование либо удаление документа внутри папки может оставить его прежний JSON; recursive compile затем прочитает старый документ снова или получит дубль _key.

replacer меняет представление экспортируемых данных на любой глубине: {_stats:{createdTime:1,systemVersion:'s'},system:{createdTime:2}} превращается в {_stats:{systemVersion:'s'},system:{}}. Наличие одноимённого пользовательского игрового поля в реальных данных не исследовано; отдельная issue о его потере без такого примера не создавалась.

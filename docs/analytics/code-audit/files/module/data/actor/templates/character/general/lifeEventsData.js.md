## Назначение файла

Собирает фиксированный объект двадцати событий жизни. Ключи 10–200 обозначают позиции в биографии; вложенное decade получает числа 1–20. Это SchemaField с заранее перечисленными ключами, а не массив или TypedObjectField.

## Условия использования

При импорте локальная const fields получает foundry.data.fields. Файл экспортирует фабрику определения схемы; значениями экземпляра и валидацией занимается Foundry, а не сама фабрика. Импортирует lifeEvent; general() включает lifeEvents() в general.lifeEvents. Файл не читает возраст и не меняет число записей при редактировании age.

## Данные и изменения состояния

Двадцать событий существуют при начальных данных независимо от возраста. lifeEventCounter регулирует число показанных карточек, не добавляет и не удаляет поля схемы. Ограничение 1–20 задано HTML-вводом; CharacterData не задаёт min/max/integer для счётчика. eachLimit не ограничивает цикл фактической длиной и при limit=21 передаёт один undefined.

Подготовка листа меняет живое actor.system.general.lifeEvents, поскольку базовый лист присвоил context.system=actor.system. Массив нужен текущему обработчику раскрытия, но больше не соответствует ключам SchemaField. В реальной модели после такой подготовки toObject(false).general.lifeEvents['10'] читает одиннадцатый элемент (исходный ключ 110), а ключ 20 становится undefined. toObject() по умолчанию берёт _source и в проверке сохраняет первоначальные данные. Это изменение в памяти, не доказанная запись испорченной биографии в БД.

Полный анализ соседних файлов остаётся их порциям; просмотр связи не повышает их статус в реестре. Проверка счётчика 21 описывает допустимые данные модели и helper; способ обхода ограничений обычной формы не исследовался. Новая отдельная проблема счётчика не регистрируется только на основании такого искусственного ввода.

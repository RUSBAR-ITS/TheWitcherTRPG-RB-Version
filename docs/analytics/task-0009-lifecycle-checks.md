## Реализовано

- `criticalWoundOperations` объединяет очередь одного клиента, ключ ID+место, проверку целей/прав, установку, стабилизацию, лечение и заживление. Публичные операции возвращают status/itemUuid/removed/reason. Нативная фабрика Item сохраняет обычный документный контракт и выбрасывает локализованный отказ при невозможности применить травму.
- Замена стадии сохраняет Item UUID/sort/folder/ownership. Стадийные system/flags/effects заменяются целиком, эффекты получают новые ID и переназначение только собственного origin. Используется **ForcedReplacement.create**, включая пустой массив эффектов; dryRun и проверка сохранённых данных. Шаблон/прочие предметы/Actor.effects не изменяются. Отмена либо исключение после возможной записи не становятся успехом и не вызывают повтор.
- Игра выбирает исходный шаблон из актуально настроенного компедиума с ожиданием индекса/документа. Ручной ввод использует выбранную стадию. Все входы сбрасывают дни/обеззараживание. Actor.addItem обходит quantity; Item.createDocuments проверяет весь пакет ключей до первой записи; неоднозначный пакет одного ключа отвергается. Item.updateDocuments проверяет будущие ключи, включая пакет изменений.
- Две независимые кнопки скрываются своими запретами. Диспетчер берёт currentTarget и только собственную травму. Создание вручную запрашивает ID и место, затем открывает лист. Конфигурация .002 сохранена.
- Заживление допускается только canHeal, без условий по тяжести/стадии. Действующее BODY влияет на срок, не сбрасывая прогресс. Один день + разовые два за обеззараживание. При достижении срока — прямое удаление, без treat. Ошибка останавливает успешный отчёт отдыха; уже изменённые ресурсы не откатываются. Самопроизвольные переходы/мировое время не добавлены.
- ru/en: добавлены подпись стабилизации и причины отказа; старые строки не удалялись. Общая арифметика эффектов/сердца остаётся в TASK-0010.

# Контракт локального поиска

Предложение [TASK-0006.001](../../tasks/task-0006.001.md), версия формата 1; согласование ожидается. Команды и ответы ниже описывают будущий инструмент .002. Сейчас query.py отсутствует. [Схема данных](format.md), [16 ожидаемых случаев](examples/queries.json).

## Запуск и команды

Предлагается Python 3 со стандартной библиотекой; на сервере проверен Python 3.14.4. Установка пакетов не требуется. Команда из корня репозитория после реализации:

```text
python3 docs/analytics/system-index/query.py find value --match exact --kind field
```

По умолчанию манифест находится рядом с query.py; корень репозитория определяется относительно каталога инструмента, не текущего рабочего каталога. Для тестового набора — глобальный параметр --dataset PATH перед командой; относительный PATH задаётся относительно текущего каталога. Все внутренние пути источников остаются относительными к корню репозитория. Инструмент не импортирует JavaScript, не открывает мир и не записывает данные при запросе.

| Команда | Результат |
| --- | --- |
| find TERM [--match exact\|contains] [--kind KIND] | Источники или сущности с совпавшим ID, путём, именем, квалифицированным именем либо alias; по умолчанию contains |
| show ID | Краткая запись источника/сущности, владелец, определение, версия и ограничения |
| neighbors ID --direction in\|out [--relation KIND] [--depth N] | Связи и адреса ближайших узлов; при N > 1 также цепочки от исходного узла |
| field ID [--access reads\|writes\|computes\|all] | Отношения обращения к полю/вычисляемому свойству; по умолчанию all |
| processes ID | Процессы и шаги с участием сущности; для src — со входом/шагами из этого файла |
| process PROC_ID | Вход, область, шаги, переходы и выходы выбранного процесса |
| details ID | Карточка источника, refs записи и их версии; текст документов не загружается в ответ |
| check [--freshness] | Структурные ошибки набора; с --freshness также проверка всех объявленных отпечатков |

find с --kind source ищет файловые записи; остальные значения — из словаря сущностей. show/details принимают точный ID источника или сущности; details также принимает rel/proc. Для neighbors допустим источник или сущность. field принимает ID field, getter или boundary.dynamic, представляющего обращение к данным. Неизвестный ID даёт явную ошибку unknown_id; retired ID отличается от отсутствия совпадений по имени.

field использует отношения, направленные к выбранному полю: reads, writes, computes. computes не означает сохранение значения, writes не доказывает запись в базу данных. Копирование рассматривается по reads/writes и passes через neighbors; payload/context должны уточнять входной объект, подготовленное значение или сохраняемое поле, если это установлено. Создание описания NumberField не выдаётся за изменение Actor.

## Совпадения, область и обход

Точные ID, пути и символы чувствительны к регистру; их байтовое написание не меняется. Для поисковых aliases применяется Unicode NFC и casefold, что позволяет искать русские пояснительные термины. contains — подстрока в тех же полях, без смыслового угадывания. Результаты разных полей одной записи объединяются по ID; одинаковые имена разных владельцев остаются отдельными результатами.

--scope SRC_ID ограничивает область; параметр можно повторять. Для find это источник определения, для отношений — источник **места обращения**, для processes — источник входа/шага. У выбранной связи сохраняется адрес внешней цели, даже если она вне scope. Без scope область — весь зафиксированный каталог, с явным учётом 612 ещё не индексированных файлов. Поиск имени может не найти сущность в необработанном файле; это ограничение видно в ответе.

Для neighbors по умолчанию depth=1; N — положительное целое число. Повторный проход уже посещённого узла не продолжается бесконечно, но зарегистрированные рёбра цикла сохраняются. При косвенном результате возвращаются ID отношений по пути; несколько мест обращения не объединяются в одну связь. Типы связей фильтруются повторяемым --relation; альтернативы объединяются. Проход по calls не исполняет условия и не доказывает достижимость ветки.

Пагинация: --limit (по умолчанию 20, положительное целое), --offset (по умолчанию 0). Порядок детерминирован по ID; шаги process сохраняют порядок записи. Для neighbors единица выдачи — отношение с контекстом пути, для field — отношение доступа, для process — шаг. Для processes — процесс с адресами подходящих шагов. Срез графа ограничен depth; это явно указано отдельно от усечения страницы. Переход к ещё не выданному шагу сохраняет ID и отметку outside_page.

show возвращает краткую запись без автоматического раскрытия вложенного графа; большие списки покрытия раскрываются отдельными запросами. Подробные карточки остаются ссылками. Запрос process всегда сохраняет вход/область и необходимые адреса выходов, даже если список шагов выдан частично.

## Форма ответа

По умолчанию — короткий текст с ID, владельцами, адресами и границами. --format json задаёт структурированную выдачу. Общий конверт:

```json
{
  "query": {"operation": "find", "term": "value", "match": "exact"},
  "items": [],
  "coverage": {"state": "partial", "scope": [], "scope_kind": "catalog"},
  "freshness": {"state": "current"},
  "gaps": [],
  "empty_reason": null,
  "page": {"total": 0, "limit": 20, "offset": 0, "truncated": false, "next_offset": null}
}
```

Это схема конверта, не результат find value: реальные ожидаемые совпадения приведены ниже и в JSON примеров. query отражает также фильтры/глубину, coverage.scope — точные src ID выбранной области. items содержат краткие сущности/источники, отношения с ID концов/местами, адреса процессов/шагов или ссылки — согласно команде. Повторяющиеся сведения о версии наследуются из manifest и источников.

coverage.state использует not_indexed/partial/complete для нужного аспекта выбранной области. Полнота отдельного getter-процесса не доказывает полноту списка процессов или всех связей файла. included/remaining соответствующего аспекта источников определяют ограничения ответа. Смешанный каталог с неполным содержательным охватом остаётся partial.

| Случай | Ответ |
| --- | --- |
| В индексированной части выбранной области совпадений нет | items=[], empty_reason=none_in_scope; coverage показывает, завершён ли сам охват |
| Весь запрошенный аспект области ещё не индексирован | items=[], empty_reason=not_indexed; coverage=not_indexed |
| Найдена динамическая/внешняя цель | Сохранён узел/отношение; gaps содержит unresolved_target/external_boundary |
| Неизвестный точный ID | Ошибка unknown_id; не маскируется сообщением «не использует никто» |
| За пределами страницы есть результаты | page.truncated=true и next_offset; total относится к выбранному запросу и глубине |

none_in_scope при partial означает отсутствие **внесённых** совпадений в этой области, а не доказательство отсутствия связи в коде. В частности, пустые writers в skillData.js не исключают писателей в остальных файлах.

freshness.state: current/stale/missing/unchecked. По умолчанию проверяются хеши 615 исходников, реестра и документов, на которые опирается выдача. Изменение одного HEAD без изменения соответствующих байтов само по себе не делает ответ stale. --no-verify явно выводит unchecked. Внешний package проверяется при доступности; его отсутствие отражается в dependencies/gaps, а не вымышленным подтверждением ядра. Хеш package подтверждает версию, не реализацию внешнего метода.

check проверяет весь набор, все активные части и внутренние ссылки. С --freshness проверяются также все карточки и reference_hashes; устаревшие/отсутствующие источники перечисляются отдельно. Успешный запрос, включая корректный пустой/частичный/устаревший ответ с отметками, возвращает код 0. check с ошибками структуры или проваленной запрошенной проверкой свежести — 1; неверный синтаксис/ID запроса — 2. Недоступная активная часть данных — ошибка загрузки, а не пустой результат.

В examples/queries.json находятся 16 случаев: command — аргументы после имени инструмента, expected — проверяемые ограничения результата, а не полный конверт. ids/relation_ids/process_ids/step_ids проверяют адреса выдачи; from_ids/to_ids/reader_ids — участников связей; ref_paths — ссылки; coverage — coverage.state; process_coverage — область конкретного процесса; total/truncated/next_offset — поля page. Массивы ID сравниваются в детерминированном порядке. note — пояснение, не поле CLI.

Ожидания установлены по трём исходникам. Во время .001 проверяются структура и соответствие этих записей коду; запуск поиска, тесты ошибок, обхода и фактическая производительность проверяются при реализации .002.

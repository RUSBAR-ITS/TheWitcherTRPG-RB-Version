## Предложение

Хранить источники, сущности, отношения и процессы в UTF-8 JSONL: одна запись на строку. Небольшой manifest.json связывает части и срез. Поиск и проверку реализовать на Python 3 со стандартной библиотекой, без сервера, установки пакетов и исполнения кода Foundry. Краткое текстовое представление выдаётся по запросу из тех же записей.

## Проверенные примеры

| Источник | Особенность для справочника |
| --- | --- |
| [statData.js](../../../module/data/actor/templates/common/stats/statData.js) | Фабрика пяти полей; value и label имеют владельца stat(), activeEffectModifiers не объявлено |
| [skillData.js](../../../module/data/actor/templates/common/skills/skillData.js) | Семь полей Skill и getter modifiedValue; собственные value/label и единственное определение activeEffectModifiers в выборке |
| [intData.js](../../../module/data/actor/templates/common/skills/intData.js) | 13 EmbeddedDataField(Skill), условная запись в source и вызов внешнего super.migrateData |

Один Skill используется в 13 вложениях Intelligence. Это 13 отношений embeds, а не 13 новых определений поля Skill.activeEffectModifiers. Пути экземпляров и определения моделей различаются. Значение modifiedValue вычисляется getter; конструирование NumberField(initial=0) не является записью модификатора в Actor.

## Почему этот вариант

| Вариант | Пригодность |
| --- | --- |
| Таблицы Markdown как основа | Удобны для объяснений, но сложнее однозначно проверять адреса и вычислять обратные связи; подробный Markdown уже есть |
| Один большой JSON | Структурирован, но чтение и изменения сильнее привязаны к целому документу |
| JSONL + небольшой локальный инструмент | Адресуемые записи, обычный поиск по строкам, ограниченные выборки и проверки стандартными средствами |
| Отдельная графовая БД/служба | Добавляет настройку и сопровождение; необходимость такого слоя сейчас не установлена |

JSONL не избавляет от смысловой проверки связей. Части делятся по области данных по мере наполнения; файл определяется манифестом, а не догадкой инструмента. Быстрые входящие/исходящие индексы строятся в памяти из тех же отношений.

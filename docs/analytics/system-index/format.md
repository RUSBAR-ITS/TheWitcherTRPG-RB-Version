# Формат справочника v1

Статус: формат TASK-0006.001 согласован пользователем 2026-09-14; локальный инструмент реализован в TASK-0006.002. [Обзор](README.md), [контракт запросов](query-contract.md), [данные примеров](manifest.json).

## Представление и файлы

JSONL: один JSON-объект на непустую строку, UTF-8, без комментариев и повторяющихся ключей. Записи упорядочены по ID внутри части; форматирование не входит в идентичность записи. Манифест — обычный JSON. Относительные paths в записях адресуют корень репозитория, paths в manifest.parts — каталог манифеста. Абсолютный observed_package_path описывает окружение проверки, а не обязательное размещение ядра.

| Файл | Назначение |
| --- | --- |
| manifest.json | Версия формата, область, срез, список частей, внешние зависимости, счётчики ID |
| sources.jsonl | Каталог исходников и подробных карточек, хеши и три аспекта покрытия |
| examples/entities.jsonl, relations.jsonl, processes.jsonl | Существующие примеры .001; все три пути в manifest.parts имеют префикс examples/ |
| examples/queries.json | Ожидаемые ответы для .002; в граф не загружается |
| data/entities/&lt;область&gt;.jsonl и аналогичные relations/processes | Предлагаемое разбиение при расширении; пока не создано и не подключено |
| README.md, format.md, query-contract.md, review-log.md | Навигация, спецификация и доказательства выполнения |

Активные части перечисляются явно и дают единственное определение каждого ID. При переносе примера в data старая часть исключается из manifest.parts; повторное подключение тех же записей — ошибка. Копии обратных отношений и полных карточек не поддерживаются.

## Идентификаторы

| Тип | Вид |
| --- | --- |
| Источник | src-000001 |
| Сущность, включая границу | ent-000001 |
| Отношение | rel-000001 |
| Процесс | proc-000001 |
| Шаг / выход | Локальный ключ, например read; полный адрес шага proc-000001/read |

Числовая часть содержит не менее шести цифр, начинается с 1. ID назначается один раз; строка, имя, путь, порядок сортировки и положение части не определяют ID при обновлении. next_ids в manifest резервирует следующий свободный номер; новые записи используют новые номера. Удалённые ID попадают в retired_ids и не используются повторно. При переименовании той же сущности ID сохраняется; замена сущности другой не маскируется сохранением её ID.

Изначальные 615 src назначены по отсортированным путям; дальнейшая пересортировка каталога не перенумеровывает их. ID аудита F/S/D/R не переиспользуются как ID справочника: связь с аудитом задаётся ссылкой.

## Манифест

Обязательные поля показаны в [manifest.json](manifest.json): format_version, dataset_id, purpose, approval, snapshot, scope, parts, next_ids, retired_ids. query_examples, dependencies и reference_hashes используются при наличии примеров/внешних контрактов.

- format_version=1; незнакомая версия требует явной поддержки, а не попытки угадать структуру.
- purpose=seed_examples обозначает начальный набор .002; approval=approved фиксирует согласование. В исторической .001 использовались proposal_examples и pending. Это независимые от состояния охвата поля; неизменный snapshot описывает версию исходных записей.
- snapshot содержит date, branch, head и совокупный source_hash. Хеш: сортированные пути, для каждого UTF-8 пути + NUL + байты файла, SHA-256.
- scope содержит адрес/хеш исходного реестра, число его файлов, выбранные источники и global_coverage. selected_sources ограничивает пример, но не удаляет остальные пути из каталога.
- parts перечисляет непересекающиеся активные файлы четырёх видов записей.
- dependencies содержит версию и проверенный отпечаток внешнего контракта; package-хеш не доказывает исполнение ядра.
- reference_hashes фиксирует документы-доказательства, используемые помимо card источника. Перечитывание неизменного документа не становится новым выполнением его тестов.

## Запись источника

Обязательные поля: id, path, sha256, card, card_sha256, coverage. Источник также является файловым узлом графа; отдельная сущность-дубликат файла не нужна.

coverage содержит definitions, relations, processes. Каждый аспект имеет state, included и remaining:

| state | Смысл |
| --- | --- |
| not_indexed | Есть путь/хеш и карточка, смысловые записи ещё не внесены |
| partial | Внесены перечисленные определения/отношения/процессы; remaining объясняет остаток |
| complete | В пределах заявленного аспекта текущего источника все значимые записи сопоставлены, остаток пуст |

included содержит существующие ID соответствующего вида. Для definitions перечисляются локальные определения, для relations — места использования в данном источнике, для processes — процессы с собственными шагами источника. Внешние границы в определения файла не превращаются.

Пример .001: все три источника остаются partial; остальные 612 — not_indexed. Даже у небольших моделей не объявлены развёрнутыми все конструкторы полей, aliases Foundry и все входящие потребители. Наполнение файлового каталога не считается индексированием 615 файлов.

## Запись сущности

| Поле | Содержание |
| --- | --- |
| id, kind, name, qualified_name | Идентификатор, вид, имя и однозначное обозначение в контексте |
| owner | ID владельца либо null у внешнего корня; не входит в строковый ID сущности |
| location | source, symbol, line_start, line_end; null допустим только у внешней границы |
| summary | Одно-два предложения о текущей роли |
| aliases | Проверяемые поисковые обозначения; пояснительные русские термины не выдаются за точный текст локализации |
| basis | source_read или historical_execution; вид основания краткого вывода |
| refs | Дополнительные адреса {path, anchor?, relation}; card выводится из источника |
| boundary | Только для kind=boundary: kind=external/dynamic, expression, причина и/или dependency |

Виды v1: class, function, method, getter, field, handler, event, setting, template, document, boundary. Файловый узел хранится в sources. Местоположение обязательно у локального определения; строки служат подсказкой на проверенной версии, symbol задаёт смысловой адрес.

Подписи и одинаковые имена не объединяют поля. stat().value — поле результата фабрики, Skill.value — поле модели. Intelligence.awareness владеет вложением Skill, но не новым определением всех полей Skill. Проекции путей экземпляров могут добавляться как aliases/контекст проверенной связи, без размножения определений.

boundary.external задаёт известное имя внешнего API без индекса его реализации. boundary.dynamic хранит фактическое выражение; это самостоятельный адресуемый узел неизвестной конкретной цели. Локальный динамический узел имеет место обращения, но не считается определением свойства Actor.

## Запись отношения

Обязательные поля: id, kind, from, to, location, basis. Концы ссылаются на существующие источники/сущности. Дополнительные поля: condition, context, payload, refs. Отсутствие condition означает только отсутствие отдельного уточнения у этой записи, а не доказанный безусловный вызов во всех контекстах.

| kind | Смысл |
| --- | --- |
| defines | Источник/объявляющая сущность → определение |
| imports | Импортирующий источник → источник импорта |
| extends / mixes | Класс → база / подключённая реализация |
| registers | Регистрирующий код → регистрируемая сущность; ключ указывается в payload |
| calls / constructs | Вызывающий код → вызываемая функция / конструктор |
| reads / writes / computes | Код → поле/данные, с различием чтения, записи и вычисления |
| passes | Производитель → потребитель с передаваемым значением |
| emits / handles | Отправитель → событие/запрос; событие/запрос → обработчик |
| renders | Код → представление/шаблон |
| refers | Документ/потребитель → документ по ID/UUID; момент разрешения указывается отдельно |
| embeds | Поле вложенной модели → определяющий класс этой модели |

owner задаёт принадлежность, defines — место объявления: например, owner Skill.value равен Skill, а defines исходит от Skill.defineSchema. Эти реквизиты описывают разные отношения.

Условие и место обращения принадлежат связи, а не только паре узлов. Для двух вызовов одной функции создаются разные записи, если различаются места/условия/данные. Сохранение ID одинакового места после сдвига строк допускается. Неявное наследование и косвенный путь не превращаются в новый прямой calls.

Обратный поиск выполняет обход тех же отношений. Узлы dynamic/external не раскрываются в угаданные реализации. Неисполняемая ссылка, импорт и регистрация не считаются доказанным вызовом.

## Запись процесса

Обязательные поля: id, name, entry, scope, coverage, basis, steps, exits, refs.

- entry задаёт entity и trigger. scope словами определяет реальный вход и предел; coverage=complete/partial относится только к этой области.
- Каждый step имеет локальный id, entity, location, summary, relations и next. Один entity может участвовать в нескольких шагах с разными ID.
- Каждый next содержит ровно step или exit, пояснение when и flow: sync, await, scheduled либо unknown.
- Выход содержит id, kind=return/error/scope_boundary/external_boundary и summary; location добавляется при известном продолжении.
- references relations должны существовать и быть применимыми к действию шага. Вложенный вызов допускает место вызова в вызывающем файле и entity вызываемого метода.
- Цикл допустим при явно указанном переходе. Неописанное продолжение помечается границей, а не успешным окончанием метода.

В примере proc-000001 полностью описывает только getter Skill.modifiedValue. proc-000002 описывает строки 25–30 Intelligence.migrateData и выходит к непройденному продолжению на строке 32. Полный Actor lifecycle, сохранение и интерфейс этими процессами не покрыты.

## Адреса, версии и доказательства

location связывает запись с конкретным src и его sha256. Для отношения учитываются версия места использования и источники его локальных концов; для процесса — шаги, отношения и вход. Для пояснений из карточки проверяется card_sha256, для refs — reference_hashes либо хеш карточки источника.

HEAD показывает срез, но изменение только docs не делает неизменные исходники устаревшими. Проверка по содержимому различает current, stale, missing и unchecked. Устаревшая строка не используется как подтверждённое место без предупреждения; индекс при поиске сам себя не исправляет.

По умолчанию инструмент проверяет хеши исходников каталога, реестра и используемых в выдаче документов. Отсутствующее ядро обозначается как непроверенная внешняя зависимость. Явный режим без проверки имеет freshness=unchecked. Граница утверждения всегда ограничена реестром и содержательным охватом; новые файлы вне зафиксированного реестра не объявляются автоматически охваченными.

## Проверяемые ограничения формата

Проверка .002 выявляет: дубли ID/ключей JSON, неизвестные виды/версии, потерянные концы, недопустимые owner/циклы владения, источники вне реестра, выход пути за корень, неверные locators, неподтверждённый complete с остатком, ссылки на отсутствующие шаги/выходы и подключение частей дважды. Цикл процесса или графа вызовов не является ошибкой сам по себе; инструмент ограничивает обход.

Базовая check проверяет структуру, ID, владельцев, внутренние ссылки, безопасные пути и согласованность покрытия. Проверка строк по содержимому исходника, членства в зафиксированном реестре и якорей документов выполняется при обычном запросе или check --freshness, только если соответствующие байты совпадают с сохранённым хешем. Для изменённого/отсутствующего источника сохраняются исторические адреса с явной отметкой. Код системы не исполняется; семантика связи проверяется по источнику и протоколу, а не гарантируется валидностью JSON.

### Выявленные отклонения

**1. Ложное сообщение о неопределённой записи новой травмы с эффектом.** Воспроизводится последовательным первым `applyCritWound` для растяжения левой ноги, без конкурирующего игрока: Item/AE уже созданы, Скорость8→6, но возвращается `failed/uncertainWrite` и сообщение «Не удалось подтвердить запись травмы…». Прямая проба `installWound` повторяет результат на другом Actor. Это **не** ранее принятое ограничение одновременного добавления с двух клиентов.

Причина проверена сравнением данных: `prepareWoundStage` ожидает у вложенного AE `start:null`; настоящий `_preCreate` записывает объект start с мировым временем. `stageMatches` исключает `_stats`, но сравнивает start и считает штатную инициализацию расхождением. Остальные сравниваемые поля совпали. Адреса: [criticalWoundOperations.js](../../module/item/criticalWoundOperations.js), prepareWoundStage/stageMatches/writeStage; [witcherActiveEffect.js](../../module/activeEffect/witcherActiveEffect.js), _preCreate; [effectApplication.js](../../module/activeEffect/effectApplication.js), initializeEffectStart. В сравнении с родительским коммитом `bc84c575` проверка травм и этот общий блок инициализации start не изменены TASK-0012; старый сервер на другом коммите отдельно не запускался. Доказательства: `wound-probe.json`, `wound-game.json`, шаги22/29. Рекомендация для следующего согласования: корректно учитывать штатную инициализацию часов в подтверждении записи, сохранив контроль настоящих расхождений; добавить регрессию первого создания из pack с AE.

### Выявленные отклонения

**1. Ложное сообщение о неопределённой записи новой травмы с эффектом.** Воспроизводится последовательным первым `applyCritWound` для растяжения левой ноги, без конкурирующего игрока: Item/AE уже созданы, Скорость8→6, но возвращается `failed/uncertainWrite` и сообщение «Не удалось подтвердить запись травмы…». Прямая проба `installWound` повторяет результат на другом Actor. Это **не** ранее принятое ограничение одновременного добавления с двух клиентов.

Причина проверена сравнением данных: `prepareWoundStage` ожидает у вложенного AE `start:null`; настоящий `_preCreate` записывает объект start с мировым временем. `stageMatches` исключает `_stats`, но сравнивает start и считает штатную инициализацию расхождением. Остальные сравниваемые поля совпали. Адреса: [criticalWoundOperations.js](../../module/item/criticalWoundOperations.js), prepareWoundStage/stageMatches/writeStage; [witcherActiveEffect.js](../../module/activeEffect/witcherActiveEffect.js), _preCreate; [effectApplication.js](../../module/activeEffect/effectApplication.js), initializeEffectStart. В сравнении с родительским коммитом `bc84c575` проверка травм и этот общий блок инициализации start не изменены TASK-0012; старый сервер на другом коммите отдельно не запускался. Доказательства: `wound-probe.json`, `wound-game.json`, шаги22/29. Рекомендация для следующего согласования: корректно учитывать штатную инициализацию часов в подтверждении записи, сохранив контроль настоящих расхождений; добавить регрессию первого создания из pack с AE.

### Остаток issue-00336: реальная цепочка создания

Доказанная цепочка: `writeStage → initializeEffectStart → actor.createEmbeddedDocuments → WitcherItem.createDocuments → assignedItemData → initializeEffectStart`. В `effectFamilies.js:139` assignedItemData безусловно обнуляет start импортируемого AE. Поэтому предварительная инициализация в writeStage не предотвращает вторую коррекцию. Вложенный AE при создании Item **не получает собственный _preCreate**: это отмечено в исходном assignedItemData и подтверждено временной диагностической обёрткой, которая не увидела вызовов. Обёртки удалены, исходники не менялись.

У получателя второй ход из трёх, исходный срок3 раунда. До его хода turnStart/turnEnd и на его ходу turnEnd сервис отправляет2, а сохраняется1. На его ходу turnStart и после его хода остаётся3 — applied. Начало/инициатива/получатель совпадают; различается duration.value, строгая проверка правильно возвращает uncertainWrite. Это последовательная операция одного клиента, не гонка и не ошибка ядра. Числовой пример непосредственно сохранён в clock-probe.json.

В94 документах штатного компедиума найдено9 конечных AE, все на1 раунд: повторное ограничение `max(0,value−1)` оставляет0, поэтому этот числовой дефект на их текущем сроке не проявился. Необходимость исправления касается конфигурируемых эффектов травм с более длинным сроком; не следует выдавать проверку штатного содержимого за проверку произвольной конфигурации.

**Поправка к границам локальных тестов .00142:**18/18 — реальный результат того стенда, но он подменял запись Item и вызывал AE._preCreate. Настоящая ветка assignedItemData была пропущена, поэтому утверждение об однократной коррекции в полном игровом пути не подтвердилось. Нужен адресный тест всей цепочки WitcherItem.createDocuments/assignedItemData, а не ещё один isolated _preCreate-тест. Решение по дополнительной правке не принято, код не изменён.

## Реализованная часть

- nonStacking/effectTypeId уже были в модели/редакторе; теперь учитываются при применении. Имя и origin не определяют семейство. При batch одного семейства на Actor остаётся последняя строка.
- На Actor повторный экземпляр заменяет прежний; у улучшения область — выбранное оружие. Сначала создаётся новая запись, затем удаляется прежняя, внутри одного withParameterChanges. При отмене/отказе записи успех не сообщается; частичный серверный отказ не объявляется транзакционным rollback.
- Источники на предметах сохраняются. Согласовано пользователем: после снятия/истечения нового источника снова действует доступный старый. Выбор по flags.TheWitcherTRPG-RB-Version.applicationOrder, при равенстве по ID. Доступность проверяется без рекурсии active/isSuppressed. Сам prepare порядок не меняет. Повторная активация Item назначает новый порядок.
- Потеря system/changes при улучшении устранена; фактическое улучшение получает transfer=false и действует на Item. Отдельные источники не удаляются ради несуммирования.
- Длительность сериализуется как value/units/expiry и отдельный start. Пустой override сохраняет шаблон;0 остаётся0; неподходящий тип/отрицательный/дробный срок отклоняется. Числа producer и обе chat-схемы сохраняют срок для hit/damage. Существующий текстовый parser заклинаний не заменялся.
- У Item используется Actor владельца при выборе combatant; коррекция очереди выполняется один раз. Подавление семейством не останавливает часы старого источника.
- Self/target/hit/damage/consume, общий query и специализированный query ожидают запись. Отсутствующий owner/GM и отмена/пустой список оружия остаются вне этой порции.

## Пакетное истечение — согласовано и реализовано

Пользователь согласовал дополнение. Нативный ActiveEffectRegistry.refresh удаляет истёкшие эффекты через modifyBatch: сначала dryRun вызывает статические методы, затем последовательно обрабатываются реальные ответы. registerEffectExpiry, подключённый в init, один раз оборачивает существующий refresh. На активном GM он охватывает уникальных Actor реестра, ограниченных context.actors, общими withParameterChanges. Ядро сохраняет расчёт времени, выбор истечения и пакетную запись; нормализация выполняется после всех ответов. На остальных клиентах wrapper только передаёт вызов. Подавленный источник продолжает отсчитывать срок.

Контрольные результаты: оба разнонаправленных временных модификатора уходят → максимум временно20, окончательно40 → запас35 остаётся35. Окончательное падение максимума90→40 обрезает запас80→40 единой записью для ПЗ и Выносливости. Увеличение20→40 не пополняет запас10. При проброшенной ошибке пакета нормализуется фактически изменённое состояние и ошибка передаётся вызывающему; транзакционный откат не обещается. Core может отдельно уведомлять об ошибках отдельных ответов без rejection всей операции.

Это узкая обёртка существующего экземпляра реестра Foundry14.367, не замена класса/часов/правил истечения. Сохраняет текущую функцию предыдущей обёртки, this и аргументы; повторная регистрация идемпотентна. Взаимодействие с модулями, которые позже самостоятельно заменяют refresh, не подтверждено игровым тестом.

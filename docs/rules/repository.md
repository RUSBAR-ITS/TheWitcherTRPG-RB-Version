# Git и организация работы

## Ветки

- `rusbar-main` — основная ветка работы над проектом.
- `original` — исходная версия для сравнения и восстановления. Текущие доработки в неё не вносятся.

Перед работой проверить ветку и рабочее дерево. При сравнении указывать конкретный коммит, поскольку имя ветки не фиксирует содержимое навсегда.

Восстановление исходников из Git и восстановление данных миров Foundry — разные операции. Переключение ветки само по себе не возвращает состояние игровых документов.

## Согласование изменений

До изменения файлов, создания или удаления веток, коммитов и публикации агент описывает предлагаемое действие и получает согласие пользователя. Выполняется согласованный перечень; новые решения и расширение объёма сначала обсуждаются.

Сохранять незакоммиченные изменения, не относящиеся к поручению. Не использовать сброс или очистку для удаления чужой работы. Сообщение коммита должно соответствовать фактически выполненным изменениям.

## Версия системы

Источник текущей версии — поле `version` в [system.json](../../system.json). Формат: `A.B.C.NNNNN`, например `14.3.1.00003`.

- Первые три компонента (`A.B.C`) меняются только по прямому указанию пользователя: переключением релизов управляет он.
- Последний компонент — счётчик изменений форка с ведущими нулями до пяти цифр. При каждом следующем завершённом согласованном изменении репозитория, включая код, настройки, контент и документацию, увеличивать его на единицу: `14.3.1.00003` → `14.3.1.00004` → `14.3.1.00005`.
- Повышать счётчик один раз на согласованное изменение целиком; сопутствующие правки документации и справочника входят в то же изменение. Не повышать его отдельно за каждый файл, промежуточное сохранение или проверку. Чтение и обсуждение без правок версию не меняют.
- Текущая согласованная правка названия и введение этого правила устанавливают `14.3.1.00003`. Самостоятельно менять первые три компонента или сбрасывать счётчик нельзя.
- Вместе с версией обновлять запись в CHANGELOG, описание манифеста и зависимые хеши справочника. Объём проверок выбирать по [правилам тестирования](testing.md#объём-проверок-справочника).

При публикации существующий [release workflow](../../.github/workflows/release.yml) подставляет в `version` тег релиза. Поэтому тег выпуска должен соответствовать полной согласованной версии, включая счётчик. Сам workflow этим правилом не изменяется.

## Доступ

Права, владельцы и группы регулируются [file-access.md](file-access.md). Согласование изменения содержимого файла не является поручением изменить его права.

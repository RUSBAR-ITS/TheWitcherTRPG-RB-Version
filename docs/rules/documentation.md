# Ведение документации

## Согласование

Создание, изменение и удаление документов предварительно согласовывается с пользователем. Задачи и архитектурные решения формируются совместно с ним; агент не назначает работы и приоритеты по собственному наблюдению.

## Назначение разделов

- `docs/README.md` — актуальный README и навигация. README репозитория ведёт сюда.
- `docs/CHANGELOG.md` — выполненные изменения.
- `analytics` — исследования конкретной версии кода, факты и открытые вопросы.
- `issues` — отдельные документы о потенциальных, открытых и закрытых проблемах.
- `rules` — правила работы с репозиторием.
- `tasks` — согласованные задачи и ТЗ.
- `documentation` — описание реализованной системы и журнал согласованных решений.

Сохранять различие между наблюдением, предложением, принятым решением и выполненной реализацией.

## Имена и ссылки

Документы пишутся по-русски. Для файлов используются понятные имена латиницей в `kebab-case`; README и CHANGELOG — в верхнем регистре.

Для файлов репозитория использовать относительные ссылки. Пути сервера указывать только как сведения о текущем окружении, когда они нужны читателю.

## Проблемы

Каждая проблема оформляется отдельным файлом `issue-00001.md` по [шаблону](../issues/templates/issue.md). Нумерация единая для `potential`, `open` и `closed`; ID сохраняется и не переиспользуется.

Статус определяется каталогом. При согласованном изменении статуса перемещается тот же документ с прежним именем, обновляются реестр и ссылки на него. Подробный порядок регистрации и подтверждения — в [issues.md](issues.md), реестр — в [issues/README.md](../issues/README.md).

Регистрация проблемы не создаёт задачу и не разрешает исправление. Подробное описание проблемы хранится в её карточке; аналитика и задачи ссылаются на неё, когда это необходимо.

## Задачи

Нумерация начнётся с `TASK-0001`. Каждая созданная после согласования задача получает постоянный ID и путь. Изменение статуса не требует перемещения документа. Созданные ID не переиспользуются.

Реестр — [tasks/README.md](../tasks/README.md), общий шаблон — [task.md](../tasks/templates/task.md). Наличие шаблона не означает наличия задачи.

Статусы: `draft` — проект уточняется; `planned` — работа поставлена в очередь; `in-progress` — выполняется; `done` — критерии выполнены; `cancelled` — отменена. Статус не заменяет согласования конкретных изменений.

## Аналитика и решения

Исследование содержит дату, ветку/коммит, источники и пределы выполненной проверки. При изменении исследуемого кода пересмотреть применимость выводов.

В [журнале решений](../documentation/decisions.md) фиксировать согласованное решение, дату, причину и состояние реализации. Не заполнять журнал предполагаемыми решениями.

После одобренных изменений поддерживать согласованность README, документации, проблем, задач и CHANGELOG. Проверять локальные ссылки, Markdown и отсутствие случайных пробелов в конце строк.

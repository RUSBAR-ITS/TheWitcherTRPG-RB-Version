# Проверки

Состав проверок определяется согласованной работой. Результат должен показывать, что действительно выполнено, на какой версии и какие свойства этим подтверждены.

## Текущие инструменты

В [package.json](../../package.json) есть команды сборки и извлечения компедиумов; команда `npm test` не определена. Создание тестового стенда не считается поставленной задачей.

## Принципы

- Проверять наблюдаемый результат, а не совпадение теста с внутренними шагами реализации.
- Для модели или обработчика использовать настоящий код, если проверяется именно его поведение.
- Ожидаемый результат не вычислять той же функцией, которую проверяет тест.
- Явно обозначать подмену окна, записи в БД или других зависимостей.
- Различать локальную проверку, браузерный сценарий, сохранение документов и работу нескольких клиентов.
- Не выдавать запланированную проверку за выполненную.

Для документации достаточно проверить содержание, ссылки, структуру Markdown и состав изменений. Игровые тесты не требуются только из-за изменения Markdown.

Команды сборки и извлечения packs записывают данные. Их запуск согласовывается как действие с записью, а не используется как обычное чтение.

## Отчёт

Записывать команду или сценарий, фактический результат и ограничения. Успешное локальное чтение не подтверждает HTTP-доступ службы Foundry; применимые правила доступа находятся в [file-access.md](file-access.md).

# Диагностика Witcher

Модуль 0.1.0 создан в `/var/lib/foundryvtt/Data/modules/witcher-trpg-diagnostics`; его README содержит API, ограничения и инструкции. Серверная инструкция — `collector/README.md` этого модуля. [Задача и результаты приёмки](../tasks/task-0007-witcher-diagnostics.md).

Код и тесты готовы. Постоянная служба/nginx, доступ foundry к новым файлам и включение модуля в мире ещё не применены. Пройденный браузерный сценарий использовал настоящие документы тестового мира и временную доставку файлов/запросов; это не доказательство штатного развёртывания.

После подключения в настройках **Диагностика Witcher** вводится ключ сборщика для текущей вкладки. В заголовке листа Actor появляется **Снимок состояния**. Команда:

```js
await game.modules.get("witcher-trpg-diagnostics").api.captureSnapshot({
  actorUuid: "Actor.…",
  reason: "Проверка текущих эффектов"
});
```

Можно передать tokenUuid вместо actorUuid для конкретного токена либо не передавать UUID при выборе ровно одного токена. Снимок содержит исходные/подготовленные данные, предметы, эффекты, настройки и состояние библиотек. Он ничего не исправляет и не пересчитывает принудительно. Вызов работает при выключенном журнале.

`delivery.status === "persisted"` — сборщик подтвердил запись; snapshotId позволяет найти файл. При отказе последний снимок скачивается через меню или `api.downloadSnapshot()`. В памяти вкладки сохраняются три последних снимка до перезагрузки; ключ тоже не переживает перезагрузку.

Журнал включается отдельно настройкой **Записывать события этой вкладки**. `api.status()` показывает счётчики и ошибки доставки, `await api.flush()` отправляет очередной пакет. Полный путь внедрения, ограничения доступа, формат JSON/JSONL и сроки хранения описаны рядом со сборщиком.

[Стенд Playwright / TASK-0008](../tasks/task-0008-foundry-browser-tests.md) сможет использовать этот API после реализации стенда и подключения модуля. Диагностика браузера агента и диагностика браузера пользователя — разные сессии.

## Общее описание проблемы

visible проверяет только rolls[0].options.fumble; applyFumble поддерживает только точные constructor AttackMessageData/DefenseMessageData и для других типов ничего не делает.

## На что влияет в системе

Контекстное меню провальных бросков навыков и других сообщений общего броска может предлагать действие, которое не выводит результата.

## Почему это проблема

Видимость пункта и наличие обработчика используют разные условия. extendedRoll может присвоить fumble любому входному messageData, включая base и damage; выбор класса происходит только после нажатия.

## Предложение по изменению

После согласования определить поддерживаемые типы результата провала и синхронизировать видимость с обработкой. Возможные решения — скрытие пункта для неподдерживаемых сообщений либо отдельное согласованное поведение для них; вариант не выбран. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Группа 13: BaseMessageData, обычный объект и subclass AttackMessageData с Roll.options.fumble=true дали visible=true; callback завершился без ChatMessage.create. Точный AttackMessageData/DefenseMessageData из группы 12 создаёт результат. Callback вызван с HTMLElement-фасадом, контракт которого сверён с Foundry ContextMenu и jQuery:false. Реальный мир/меню не запускались. Регистрация base и другие типы имеют отдельное наблюдение issue-00005; оно не устраняет различие условий внутри fumble.js.

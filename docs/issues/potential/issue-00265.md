## Общее описание проблемы

Условие fallback option в weapon-attack.hbs содержит eq с одним аргументом и повтор elemental. С текущими helpers итоговое условие эквивалентно piercing===false.

## На что влияет в системе

Список типов повреждения оружейной атаки: unavailable появляется рядом с разрешёнными slashing/bludgeoning/elemental.

## Почему это проблема

Недоступный тип предлагается при наличии обычного доступного типа. Назначение fallback следует из имени/расположения, но подтверждение пользователя ещё необходимо.

## Воспроизведение и доказательства

Группа 23: настоящий Handlebars и исходные helpers eq/or, 16 наборов bool. slashing=true, остальные=false → ['slashing','unavailable']; piercing=true → ['piercing']; всеfalse → ['unavailable']; всеtrue → четыре типа без unavailable. В целом unavailable присутствует ровно при piercing=false. Ожидание — fallback не предлагается как дополнительный тип при доступных типах.

Нормальный тип стоит первым; автоматический выбор unavailable вместо него не воспроизведён. Влияние вручную выбранного unavailable на весь расчёт сопротивлений не проверялось.

Статус: `potential` — по каталогу и [реестру проблем](../README.md).

## Общее описание проблемы

Каждая группа передаёт подпись в options.label внешнего EmbeddedDataField(Skill), а Skill.defineSchema(label) пытается использовать её как свой аргумент. В Foundry 14.367.0 DataModelSchemaField вызывает model.defineSchema() без аргумента: подпись не попадает ни в initial поля Skill.label, ни в метаданные Skill.isVisible.label.

## На что влияет в системе

В изолированном new CommonActorData({}) все 52 Skill.label равны undefined. Повторное создание из toObject() заполняет label миграциями групп, но метаданные isVisible.label по-прежнему отсутствуют. Настройки монстра передают в formGroup именно это поле без собственной подписи; реальный DataField.toFormGroup выбирает техническое имя поля: в исходном непривязанном сценарии isVisible, а с Actor-родителем — полный system.skills.*.isVisible (уточнение TASK-0003.029 ниже).

## Почему это проблема

Внешний label и подпись вложенного поля — разные уровни схемы. Код явно пытается передать подписи навыков, но механизм не передаёт аргумент. Конкретный вид нового Actor после клиентского создания зависит от дополнительных миграций и этой проверкой не установлен.

## Предложение по изменению

Согласовать явный способ задания ключа подписи экземпляру навыка и подписи поля видимости. Проверить создание с пустыми данными, загрузку существующей записи и конфигурацию монстра. Не считать перенос label в другое место достаточным без проверки жизненного цикла. Предложение требует отдельного согласования.

## Воспроизведение и доказательства

1. Загрузить реальные DataModel, TypeDataModel и fields из установленного ядра, затем CommonActorData.
2. Создать модель из {}, проверить 52 label и метаданные isVisible.
3. Создать вторую модель из first.toObject(): её label заполнены, isVisible.label остаётся undefined.
4. Вызвать реальный toFormGroup на поле isVisible с подставленным готовым input и перехватом createFormGroup.

**Ожидаемый результат:** Подпись настройки каждого навыка должна различать навыки; такое назначение следует из явно передаваемых WITCHER.skills.*.label.

**Фактический результат:** 52 отсутствующих label при первом создании; 52 заполненных после повторного создания. У 52 полей isVisible нет label. toFormGroup возвращает groupConfig.label='isVisible'.

**Пределы проверки:** Подменены готовый input и createFormGroup, DOM не создавался. Браузер, создание/сохранение реального Actor и стадия локализации итоговой формы не запускались. Повторная миграция проверена только указанным локальным сценарием.

Исполняемый сценарий и результаты — в [сверке TASK-0003.002](../../analytics/code-audit/review-log.md#task-0003002).

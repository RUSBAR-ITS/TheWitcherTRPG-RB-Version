## Общее описание проблемы

Если в диалоге изготовления не хватает компонентов, callback читает item.system.associatedItem.name. Связанный результат рецепта необязателен, поэтому у рецепта без него доступ к name вызывает TypeError до ui.notifications.error.

## На что влияет в системе

Вывод объяснения отказа при выборе реального изготовления. Подтверждён обычный ремесленный вход; в алхимическом callback есть такое же обращение.

## Почему это проблема

У модели разрешён пустой результат, а realCraft содержит специальный успешный сценарий изготовления без результата. Отсутствие связи само по себе не запрещает рецепт, но обработчик ошибки предполагает обязательное наличие Item.

## Предложение по изменению

Формировать сообщение о недостающих компонентах без обязательного связанного Item; согласовать запасное имя для рецепта без результата. Код не менялся.

## Воспроизведение и доказательства

Группа 09: настоящий _craftingCraft, рецепт требует три компонента, у Actor их нет; realCraft=true и associatedItem отсутствует. Callback выбросил TypeError, уведомлений не было. Тот же сценарий с доступным associatedItem дал одно уведомление. Группа 15 проверила аналогичную ветку алхимии только после явного адаптера отсутствующего populateAlchemyCraftComponentsList в fixture: в текущем коде этот вход раньше останавливается на issue-00037. Диалог, UUID resolver и запись уведомлений подменены; данные мира не менялись.

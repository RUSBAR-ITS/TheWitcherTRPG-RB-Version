## Общее описание проблемы

applyActiveEffectToActor записывает duration.rounds во входной эффект, а копию создаёт через clone. В Foundry 14.367 современная duration хранится иначе; присваивание подготовленному объекту не изменяет _source и не попадает в clone.

## На что влияет в системе

Заданная длительность эффектов заклинания, попадания, урона и других вызовов этого общего маршрута. Доказан owned-путь копирования; полный сетевой путь не проверен.

## Почему это проблема

Параметр duration передаётся вызывающими функциями для применения эффекта с нужным сроком, но копия сохраняет исходное значение. Формы аргумента Document, toObject и JSON-данные ведут себя неодинаково.

| [module/actor/mixins/castSpellMixin.js](../../../module/actor/mixins/castSpellMixin.js) | Передача damage.duration:253–267 |

## Предложение по изменению

Перейти на согласованные поля duration/start текущего ядра и задавать их в данных создаваемой копии, не в подготовленных данных источника. Явно передавать duration между клиентами; проверить документы и сериализованные данные. Исправление не согласовано.

## Воспроизведение и доказательства

Настоящий BaseActiveEffect 14.367 с duration={value:5,units:'rounds'} и настоящей моделью системы передан в исходный applyActiveEffectToActor. Запросы duration=0 и 2 изменили только effect.duration.rounds; source и clone остались value=5. При undefined также сохранилось 5. У прямого effect.toObject() запись rounds получила TypeError: Cannot set property rounds of #<Object> which has only a getter. JSON-roundtrip данных с современным value=5 при запросе 2 дал копию value=5. Remote-подмена записала data общего query из двух аргументов: UUID и список, без третьего duration.

**Пределы проверки:** Поля, миграция legacy-данных, toObject и clone — настоящие тела ядра. Actor, createEmbeddedDocuments, UI и query подменены. Реальные клиентские preCreate, сеть и БД в проверке копии не выполнялись. Отдельный start улучшения описан в issue-00050.

## Общее описание проблемы

WitcherDiagramSheet._prepareContext относит любую запись с UUID к knownCraftingComponents и создаёт {id, ...fromUuidSync(uuid), quantity} ?? component. При null создаётся объект только с id/quantity; правая часть ?? никогда не возвращает исходную запись.

## На что влияет в системе

Сохранённый материал с уже недоступным связанным Item отображается без имени и изображения. Имя в модели при этом есть, но ручной редактор имени находится только в unknown-ветви, куда запись с UUID не попадает.

## Почему это проблема

Обогащение модели сохраняет исходное имя при неразрешённом UUID, а последующая подготовка UI выбрасывает его. Неудача разрешения не должна скрывать уже имеющиеся данные строки.

## Предложение по изменению

Согласовать резервное представление и способ редактирования недоступной ссылки, сохраняя ID, имя и количество строки. Проверять факт разрешения UUID, а не только наличие строки. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Настоящая DiagramData содержала запись name='Missing remembered name',quantity3 и UUID, для которого resolver вернул null. После prepareDerivedData имя сохранилось; настоящий _prepareContext вернул known-запись {id,quantity:3}, а имя/картинка в HBS оказались пустыми. Контроли с настоящим BaseItem и без UUID сохранили ожидаемые имена; id строк остались корректными.

Ожидаемое поведение обосновано выше; наблюдение не заменяет подтверждения пользователя. Методика — [журнал сверок](../../analytics/code-audit/review-log.md#task-0003016).

**Пределы проверки:** UUID API заменён картой; BaseItem и модели настоящие. Причина недоступности Item в конкретном мире, pack-кеш и браузер не проверены.

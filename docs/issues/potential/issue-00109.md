## Общее описание проблемы

RaceData.enrichedText готовит value/enriched/systemField для четырёх особенностей, а WitcherCharacterSheet._prepareCharacterData помещает их в context.enrichedText.race. Шаблон tab-profession.hbs вместо подготовленного HTML передаёт editor исходные race.system.perkN.description. Helper editor и стандартный createEditorInput сами текст не обогащают.

## На что влияет в системе

Показ описаний расы на листе персонажа. В проверке @UUID-разметка осталась исходным текстом в HTML, хотя подготовленный результат уже присутствовал в контексте. Собственная форма race Item передаёт enriched корректно.

## Почему это проблема

Модель и лист специально вычисляют обогащение для показанного описания, но потребитель его теряет. Это разрыв передачи данных, независимо от содержания игровых правил. Контрольная форма того же Item сохраняет различие исходного текста редактора и HTML для показа.

Во внешнем ядре Foundry 14.367: /opt/foundryvtt/client/applications/handlebars.mjs:225–230 передаёт content как value в createEditorInput; /opt/foundryvtt/client/applications/forms/fields.mjs:107–125 в стандартной ветви вставляет config.value в editor-content. CONFIG.TextEditor.engines по умолчанию пуст в /opt/foundryvtt/client/config.mjs:2825; обработка внешним движком отдельно не проверялась.

## Предложение по изменению

После согласования использовать подготовленный enriched для показа, сохраняя исходный value для редактирования. Проверить корректный способ редактирования вложенного race Item на Actor-листе: текущий target имеет вид race.system.perkN.description, но сохранение через этот путь в данном исследовании не проверялось. Не считать простую замену текста полноценным исправлением всего редактора без проверки. Изменения не согласованы и не выполнялись.

## Воспроизведение и доказательства

1. В настоящей RaceData задать perk1.description='<p>@UUID[Item.abcdefghijklmnop]</p>', остальные описания оставить пустыми.
2. Вызвать настоящие enrichedText/createEnrichedText с TextEditor, возвращающим различимый HTML-маркер; проверить неизменность source.
3. Настоящим _prepareCharacterData получить enrichedText.race.
4. Отрендерить исходный блок расы из tab-profession.hbs с настоящими Handlebars, editor и createEditorInput; DOM заменить минимальным фасадом, CONFIG.TextEditor.engines оставить пустым.
5. Для контроля отрендерить race-sheet.hbs с настоящим formGroup/HTMLField и перехватом создания ProseMirror-элемента.

**Результат:** все четыре editor на Actor получили raw value; подготовленный маркер отсутствует, @UUID осталась в HTML. В форме Item все четыре поля получили свои value/enriched и корректные system.perkN.description. Подготовка source не изменила. [Методика и сверка](../../analytics/code-audit/review-log.md#task-0003018).

**Пределы:** обогащение и DOM подменены; настоящие ссылки на документы не разрешались, браузерный вид/клик/сохранение редактора и внешние модули не проверены. Наблюдение касается передачи и стандартного построения HTML, а не доказанной ошибки сохранения. tab-profession.hbs и лист Actor проверены как потребители, не получили статуса полного пофайлового разбора.

Сопоставлена [issue-00013](issue-00013.md): она относится к другим полям/шаблону монстра, где .value передан в именованный аргумент enriched. Здесь другой consumer и helper editor; отдельная карточка сохраняет точную локализацию исправления. Подтверждение пользователя не получено.

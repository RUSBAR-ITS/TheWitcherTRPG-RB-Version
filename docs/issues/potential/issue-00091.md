## Общее описание проблемы

Оба списка consumeProperties.effects/removesEffects состоят из SchemaField(itemEffect()) внутри ArrayField. itemEffect не определяет id, добавление создаёт только {percentage:100}, но форма выводит effect.id и обработчики ищут запись по этому полю.

## На что влияет в системе

В настройках расходуемого алхимического или прочего предмета добавление строки доступно, а редактирование имени/статуса завершается ошибкой. Кнопка удаления не убирает строку. Оба списка затронуты.

## Почему это проблема

Форма и обработчик требуют идентификатор, который модель не хранит. Пустой data-id из HTML не равен отсутствующему obj.id: findIndex даёт -1, filter оставляет все элементы. Это не вопрос выбора игрового правила.

## Предложение по изменению

Согласовать адресацию элементов массива: устойчивый идентификатор, предусмотренный моделью, либо корректную работу по индексу с учётом обновлений. После выбора проверить оба списка и весь цикл добавления, редактирования, удаления и повторного открытия формы. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

В настоящих AlchemicalData/MutagenData/ValuableData входной id удаляется при очистке. Настоящий HBS даёт data-id=''. Исходный _onEditEffect на обоих массивах выбрасывает TypeError: Cannot set properties of undefined до update. _oRemoveEffect передаёт неизменившийся массив. _onAddEffect добавляет {percentage:100}, не назначая ID. Проверены фактические поля формы: name для effects и statusEffect для removesEffects.

Основание ожидаемого поведения указано выше; вывод не заменяет подтверждения пользователем. Методика — [журнал сверок](../../analytics/code-audit/review-log.md#task-0003015).

**Пределы проверки:** Реальные модели, HBS и методы; DOM события и Item.update подменены. Нет браузерного submit, мира или записи в БД. Изолированная ветвь текста on из issue-00060 проверялась только после ручной вставки временного id в подготовленную запись.

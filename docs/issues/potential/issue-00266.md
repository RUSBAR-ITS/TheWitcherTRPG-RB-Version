## Общее описание проблемы

weaponAttack формирует ammunitionOption конкатенацией element.name, затем HBS выводит её через тройные фигурные скобки. HTML в имени может изменить структуру option.

## На что влияет в системе

Список выбора ammo, отображение имён с разметкой и передаваемый ID.

## Почему это проблема

Имя предмета должно быть текстом подписи, а в проверенном HTML оно создаёт дополнительный пункт, которому не соответствует Item. Исполнение произвольного JavaScript не доказано и не заявляется.

## Предложение по изменению

После согласования передавать список объектов в шаблон/штатный helper с экранированием либо экранировать значения при сборке option. Конкретный вариант ещё не согласован.

## Воспроизведение и доказательства

Группа 24: имя ammo 'Arrow</option><option value="FAKE">Inserted'; настоящий Handlebars, parse5.parseFragment. Получены два option: AMMO и FAKE, при одном исходном Item. Контроль обычного имени даёт один option. Ожидание — один пункт с текстовым именем.

DialogV2 sanitization/браузер/XSS не запускались; доказано изменение подготовленного HTML, а не обход безопасности Foundry.

[Методика, фиксированные входы и результаты](../../analytics/code-audit/review-log.md#task-0003041). Запуск использовал исходные функции и настоящие модели/Handlebars/Roll; Actor, Dialog, DOM-форма, запись и доставляемые сообщения — фасады. Не все группы исполняют extendedRoll целиком: формулы захвачены на его границе, один отдельный проход использует настоящий helper. Для CSS проверялись исходники и спецификация.

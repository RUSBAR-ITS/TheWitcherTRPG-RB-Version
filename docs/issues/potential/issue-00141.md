## Общее описание проблемы

fromItem передаёт createTokenEmanation дальность templateSize/2/canvas.scene.grid.distance. Ядро затем переводит её в пиксели по сцене конкретного токена.

## На что влияет в системе

Размер привязанной области, особенно когда зависимые токены находятся в другой сцене.

## Почему это проблема

При неизменных настройках Item и токене смена только просматриваемой сцены меняет результат. API уже делает преобразование по token.parent; внешний делитель использует несвязанную сцену.

## Предложение по изменению

После согласования определить единицы поля и смысл радиуса/диаметра, затем переводить размер через целевую сцену/API без влияния чужой сетки. Множитель 2 не менять на основании догадки о правилах. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Группа 11: один и тот же токен со сценой distance5, size100 и Item size10. При canvas distance5 core-create получил radius20px; при canvas distance10 — radius10px. Настоящее тело RegionDocument.createTokenEmanation вычисляет radius=range*token.parent.dimensions.distancePixels.

[Методика и результаты сверки](../../analytics/code-audit/review-log.md#task-0003022). Ожидание основано на контрактах кода, без утверждения о правилах книг.

**Пределы проверки:** Создание заменено; это проверка зависимости геометрии, не сверка игровых правил. Дополнительно отмечен default gridBased=false в API эманации, без отдельного решения о желаемом виде сетки.

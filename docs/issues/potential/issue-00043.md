## Общее описание проблемы

Когда update содержит system, но не changes, _preUpdate обращается к отсутствующему массиву. При изменении только changes прежнее applyAfterCalculations=true игнорируется и всем строкам назначается initial.

## На что влияет в системе

Частичные обновления эффектов из скриптов и любых интерфейсных путей с такой формой payload. Полная форма настройки отдельно не проверялась.

## Почему это проблема

Document.update допускает частичный payload. Обработчик не должен требовать несвязанный массив; фаза существующего эффекта не должна меняться только из-за отсутствия флага в обновлении. Последнее ожидаемое поведение требует подтверждения пользователя.

## Предложение по изменению

Разделить обработку наличия changes и изменения флага, определить фазу с учётом текущего значения документа. Согласовать, что происходит с уже сохранёнными changes при обновлении только флага; проверить полную форму и частичный update. Исправление не согласовано.

## Воспроизведение и доказательства

Исходный _preUpdate выполнен с разрешающим super и текущим system.applyAfterCalculations=true. Payload {name:'New'} прошёл; {system:{applySelf:true}} и {system:{applyAfterCalculations:true}} дали TypeError: Cannot read properties of undefined (reading 'forEach'). {system:{changes:[{key:'x',phase:'final'}]}} превратился в phase='initial'; тот же payload с applyAfterCalculations:true получил final. Ветвь super=false возвращает false без обработки.

**Пределы проверки:** Выполнено тело метода в малом контексте, без Document.update в мире и без формы. Core _preUpdate Foundry прочитан: он не достраивает отсутствующие changes. Изменение сохранённых данных не выполнялось.

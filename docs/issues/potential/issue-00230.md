## Общее описание проблемы

currencyConverterListeners при каждом вызове делает новый bind и addEventListener для всех найденных кнопок. Дедупликации или снятия прежней подписки нет.

## На что влияет в системе

Число открываемых окон при повторной регистрации на сохранившемся DOM-элементе.

## Почему это проблема

Базовый V2 после render вызывает activateListeners на всём element. При частичной замене других частей кнопка инвентаря может сохраниться; повторный bind является новым listener.

## Предложение по изменению

После согласования сделать привязку устойчивой к повторному вызову либо привязывать её только к заново созданной части. Проверить полный и частичный render; простой полный render с новыми кнопками не обязан дублировать обработчики. Изменения не согласованы и не выполнялись.

## Воспроизведение и доказательства

Группа18: настоящий регистратор и Node EventTarget: первая привязка/клик→1 вызов; вторая привязка к тому же узлу/клик→ещё2; новый узел/одна привязка→1. Core /opt/foundryvtt/client/applications/api/handlebars-application.mjs:191–224 заменяет только entries отрендеренных частей. Настоящий браузерный render не запускался; удвоение при любом полном render не заявляется. Наблюдение отличается от issue55, где речь о добавленных элементах мастера/datalist.

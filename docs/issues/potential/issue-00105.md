## Общее описание проблемы

Если компонент отсутствует у исполнителя, но у требования есть UUID, prepareData без проверки добавляет результат await fromUuid в missingComponents. Для null следующий prepareDialogTemplate обращается к oc.img/oc.name и падает.

## На что влияет в системе

Диалог не открывается для рецепта с недоступной ссылкой на компонент, хотя его сохранённое имя известно. Пользователь не получает ни строку unknown, ни специализированное уведомление о недоступном материале.

## Почему это проблема

Ветка отсутствующих компонентов должна сохранять возможность показать требование или сообщить о конкретной неразрешённой ссылке. Результат resolver может быть null, что предусмотрено Foundry API и уже обрабатывается для самого рецепта.

## Предложение по изменению

Согласовать обработку неразрешённого компонента: явное сообщение либо сохранение исходного требования для ручного ввода. Согласованно проверить список, цену, чат и повторное открытие; не считать null полноценным Item. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Создан настоящий рецепт с валидным UUID Item.unknowncomponent и именем Gone. UUID-фасад возвращал null; настоящий prepareData вернул missingComponents=[null], настоящий prepareDialogTemplate дал Cannot read properties of null (reading 'img'). Более ранняя проверка самого рецепта успешно пройдена.

Основание ожидаемого поведения приведено выше; результат воспроизведения не заменяет подтверждения пользователем. Методика и контрольные сценарии — [журнал сверок](../../analytics/code-audit/review-log.md#task-0003017).

**Пределы проверки:** Недоступный документ задан картой resolver; реальные packs/права/загрузка не проверялись. Это другая точка потери обработки ссылки, чем issue-00095 в редакторе рецепта, поэтому ID отдельный.

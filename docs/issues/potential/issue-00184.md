## Общее описание проблемы

extendedRoll ожидает toMessage, затем запускает setFlag для каждого аргумента flags без await; возвращаемый Promise<Roll> уже может завершиться при незавершённых обновлениях сообщения.

## На что влияет в системе

Сообщения словесного боя: createVerbalCombatFlags задаёт verbalCombat/damage, а обработчик кнопки читает их через getFlag. Между созданием сообщения и сохранением флагов данные ещё недоступны.

## Почему это проблема

Возврат общего броска не гарантирует завершение всех его записей. Обработчики/отображение сообщения могут получить неполный набор флагов; отклонение Promise setFlag не включено в Promise extendedRoll.

## Предложение по изменению

После согласования включить данные в первоначальное создание сообщения либо ожидать согласованное сохранение флагов до завершения операции. Отдельно определить контракт flags при showResult=false: сейчас этот аргумент игнорируется; текущие найденные потребители передают дополнительные flags только при выводе сообщения. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Группа 10: управляемый Promise toMessage удерживал extendedRoll; после его разрешения два setFlag оставались pending, но await extendedRoll завершился. До разрешения setFlag поле отсутствовало, после разрешения появилось. Проверены массив, единичный объект и null. Это выполнение настоящего extendedRoll с фасадами записи, не утверждение о длительности сетевого окна или о фактически произошедшей потере данных в мире.

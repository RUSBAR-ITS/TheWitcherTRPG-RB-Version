## Общее описание проблемы

Общая конфигурация предлагает все WITCHER.attackOptions, включая itemUse. Но general.hbs содержит секции только melee/ranged/spell и не выводит itemUseAttackSkill, хотя схема и getItemAttack используют это поле.

## На что влияет в системе

Настройка нового оружия на «Использование предмета» через эту форму оставляет навык отсутствующим. В проверенной ветви атака останавливается с сообщением «Атакующий навык не настроен».

## Почему это проблема

Выбираемый вариант атаки имеет обязательного для запуска потребителя навыка, но редактор не даёт заполнить его. Существующие документы с вручную заданным itemUseAttackSkill могут работать; отсутствие поля редактора не означает отказ всех таких документов.

## Предложение по изменению

Согласовать редактор навыка itemUse и его список допустимых значений либо пересмотреть доступность этого варианта. Сверить решение со схемой и фактическим потребителем. Предложение не согласовано; код не менялся.

## Воспроизведение и доказательства

Рендер general.hbs с настоящими WeaponData/SpellData и Set из четырёх вариантов собрал 8/9 полей; itemUseAttackSkill среди них нет. Настоящий getItemAttack на WeaponData с attackOptions=['itemUse'] вернул itemUse без skill. Исходная weaponAttack остановилась на уведомлении «Атакующий навык не настроен».

Ожидаемое поведение и его основание указаны в разделе «Почему это проблема»; наблюдение не заменяет подтверждения пользователем.

**Пределы проверки:** formGroup использован из ядра, toFormGroup заменён фасадом учёта полей; полный браузерный control не создавался. Метод атаки исполнялся только до раннего уведомления, без броска и БД.

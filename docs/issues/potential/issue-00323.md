## Общее описание проблемы

Два documentUuid в общей таблице Mounted Control Loss не соответствуют ни одному документу текущего экспортного набора. Одноимённые Personal и Mount существуют с другими ID. Ссылка разрешается по UUID, а не по имени или flags.scene-packer.sourceId.

## На что влияет в системе

Обычный рекурсивный вызов общей таблицы при загрузке пакета из этого экспорта возвращает пустой массив. draw не создаёт сообщение. Самостоятельный вызов Personal/Mount по их действительным документам проходит. Установленная БД не исследована: в ней могут быть иные документы, поэтому её фактическое состояние не объявляется проверенным.

## Почему это проблема

Общий 1d1-агрегатор выбирает оба результата [1,1], но не может перейти к своим подтаблицам. Ядро пропускает отсутствующую вложенную цель без добавления её результата; текстовое имя не является резервным способом поиска.

## Предложение по изменению

После согласования исправления проверить соответствие имён/содержимого целей и заменить два documentUuid на UUID действительных Personal/Mount; затем согласованно обновить компедиум. Проверить результат из двух вложенных таблиц и отсутствие потерянных ссылок. Ни подмена данных, ни сборка, ни тест исправленного экспорта не выполнялись.

## Воспроизведение и доказательства

Все 128 RollTable и 995 результатов прошли строгую загрузку моделями Foundry 14.367. Проверка documentUuid обнаружила ровно два отсутствующих адреса, оба здесь; 252 остальных разрешаются в экспортных JSON.

В реальном roll при recursive:false получены два document-результата. При recursive:true fromUuid вызван для обоих старых UUID, фасад карты экспорта вернул undefined, итог []. Реальный draw возвратил [] без нового ChatMessage. При recursive:false draw создаёт две content-link; синтаксически правильная ссылка в HTML не доказывает существование документа.

В отдельном сценарии исходный checkIfItemHasRollTable при совпадении Item.name='Mounted Control Loss' получил тот же пустой результат и выбросил TypeError на documentCollection. Отсутствие защиты пустого массива уже описано в [issue-00039](issue-00039.md); здесь причина в ссылках конкретного экспортного файла, не новый дубль обработчика.

Существующая issue-00320 относится к пределу глубины других таблиц, issue-00321 — к непереданному модификатору. Все прежние карточки сверены по UUID/именам и механизму. БД, реальная загрузка pack, модуль scene-packer и обычные клики не проверялись.

# issue-00161 — Drop в контейнер обновляет исходный Item другого владельца

**Уточнение .00034:** [принятые решения](../open/issue-00333.md#container-decisions-00034) различают копирование Actor → мировой шаблон и перенос Actor → Actor-хранилище. Источник копии остаётся у персонажа. Самодостаточные шаблоны редактируются в Items и затем экспортируются в pack. Реализация не начата; индивидуальный статус сохранён.

**План исправления .00033:** [issue-00333, П06](../open/issue-00333.md#p06) — предлагаемые изменения, связанные файлы и проверки. План подготовлен; реализация и закрытие не выполнены, индивидуальный статус сохранён.

## Согласованное поведение — 2026-09-17 / .00032

Пользователь поручил закрепить [четыре правила контейнеров в issue-00333](../open/issue-00333.md#container-rules): импорт из мирового каталога/компедиума создаёт самостоятельную копию с новым UUID; укладка из инвентаря того же персонажа использует существующий предмет; перенос между контейнерами перемещает предмет; извлечение возвращает его в инвентарь владельца. Источник импорта сохраняется, а экземпляр при перемещении не остаётся у отправителя. Учёт игровой собственности и новая кнопка копирования не вводятся.

Правила приняты, код ещё не менялся. Технический план должен учитывать недоступные ссылки ([00156](issue-00156.md)) и частичный отказ нескольких записей ([00157](issue-00157.md)). Исходная карточка остаётся в potential; перенос и закрытие этим оформлением не выполняются. Наблюдение ниже описывает текущую неисправленную реализацию.

## Общее описание проблемы

Собственный _onDropItem проверяет тип и локальный повтор UUID, но не parent/isOwner источника. Сохраняет исходный UUID и вызывает update этого же Item, без создания копии у владельца контейнера.

## На что влияет в системе

Перенос предметов мира, другого Actor или компедиума; связь веса с исходным документом.

## Почему это проблема

При успешных правах общий источник будет помечен stored вместо переноса/копирования ожидаемому владельцу; при отказе прав две записи могут разойтись. Требуемая семантика внешнего Drop требует согласования. Обход серверных прав не утверждается.

- [module/item/sheets/WitcherItemSheet.js](../../../module/item/sheets/WitcherItemSheet.js) — 100–111, 123–134.

## Предложение по изменению

Реализовать согласованные правила из раздела выше после подготовки технического плана. Различать импорт копии, укладку и перемещение существующего экземпляра; проверить права участников и обработку отказов записи. Возможность оставить контейнер получателя со ссылкой на предмет другого персонажа больше не рассматривается как целевое поведение. Способ выполнения записей пока не определён, исправление не выполнено.

Группы 10/13: фасады world Item с parent=null и Item другого Actor с isOwner=false были приняты; parent/UUID сохранились, вызван update источника, новых документов нет. isEditable=false листа назначения останавливает общий Drop.

Пределы проверки: API update намеренно подменён; фактическая возможность обновить чужой Item/pack в Foundry не проверена. [Сценарии и перекрёстная сверка](../../analytics/code-audit/review-log.md#task-0003024).

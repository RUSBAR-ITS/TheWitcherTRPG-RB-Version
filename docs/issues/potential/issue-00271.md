## Общее описание проблемы

handleLifepathModifier сравнивает action с 'parrythrown', тогда как CONFIG задаёт 'parryThrown'.

## На что влияет в системе

Применение shieldParryThrownBonus при защите щитом; обычный shieldParryBonus имеет другой корректно совпадающий путь.

## Почему это проблема

Поле модели и стандартный action существуют, но различие регистра делает ветку недоступной при штатном имени.

## Предложение по изменению

После согласования привести идентификатор action в соответствие с конфигурацией и проверить оба вида парирования. Исправление не согласовано.

## Воспроизведение и доказательства

Группа 15: additionalTag='armor', shieldParryThrownBonus=3. action parryThrown → BASE; контроль parrythrown → BASE +3[...]. Обычный parry с shieldParryBonus=2 → BASE +2[...]. Отрицательный shieldParryBonus игнорируется; допустимость отрицательного значения по правилам отдельно не установлена.

Проверено настоящее тело helper; реальное окно и полный бонусный эффект Actor не запускались.

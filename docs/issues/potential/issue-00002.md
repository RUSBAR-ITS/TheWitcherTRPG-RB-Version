## Общее описание проблемы

В обработчике `ready` результат `game.packs.get(...)` используется без проверки существования. Если настройка `criticalWoundsPack` указывает на недоступный компедиум, вызов `getIndex` завершается TypeError и оставшиеся действия этого обработчика не выполняются.

## На что влияет в системе

В этом сценарии обработчик не доходит до регистрации `hotbarDrop`, применения выбранного шрифта, регистрации системного сокета и вызова `deprecationWarnings`. Последняя функция сейчас пустая, поэтому её пропуск сам по себе не имеет установленного пользовательского последствия.

Не утверждается, что эти части отсутствуют в текущем запущенном мире: его настройка и доступность pack не проверялись.

## Почему это проблема

Доступность одного компедиума становится условием для остальной инициализации, включая функции, которые напрямую не используют травмы. Недоступная ссылка может остаться после удаления или отключения источника данных; такой сценарий не обработан явно.

## Где конкретно локализована в коде

- [module/TheWitcherTRPG.js](../../../module/TheWitcherTRPG.js), строки 62–91: получение pack и `await criticalWounds.getIndex` предшествуют остальным действиям.
- [module/setup/settings.js](../../../module/setup/settings.js), строки 2–14: настройка и значение по умолчанию `TheWitcherTRPG.criticalWounds`.
- [system.json](../../../system.json), строки 51–56: объявление соответствующего компедиума.

## Воспроизведение и доказательства

Проверка выполнена на исходном теле callback в Node vm. Однострочные импорты удалены из загружаемого текста, внешние функции и объекты заменены минимальными подменами; `Hooks.once` сохраняет callback для вызова. Файлы системы не изменялись.

1. При `game.packs.get`, возвращающем `undefined`, вызван сохранённый `ready`.
2. Получено `TypeError: Cannot read properties of undefined (reading 'getIndex')`. Ни один из следующих шагов не был достигнут.
3. Контрольный сценарий с существующим pack и успешно завершившимся `getIndex` достиг последовательности `getIndex → hotbarDrop → socket → deprecations`.

Ожидаемый результат для обсуждения — явная обработка недоступного источника без неявной остановки независимых действий. Фактический результат подтверждён для подменённого окружения; полная загрузка Foundry и реальные пользовательские последствия не воспроизводились.

Отказ Promise от `getIndex` по структуре кода также прерывает callback; отдельный сценарий такого отказа в этой проверке не выполнялся.

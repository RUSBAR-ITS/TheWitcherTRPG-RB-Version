## Общее описание проблемы

Общая схема и формы содержат отдельный applyRangedMeleeBonus. Поиск по module/ нашёл его только в определении поля: weaponAttack и атака профессии рассчитывают бонус по applyMeleeBonus.

## На что влияет в системе

Настройка бонуса урона для дальнего варианта предмета/профессиональной атаки. Пользователь может менять флаг формы, но отдельное значение не читается расчётными обработчиками.

## Почему это проблема

В интерфейсе представлены две раздельные настройки, а вычисление использует только одну. Это проверка соответствия конфигурации потребителю, не утверждение о настольных правилах применения бонуса.

## Предложение по изменению

После согласования определить применение двух полей по выбранному attackOption и согласовать это с правилами системы; затем связать расчёты с выбранной настройкой. Игровая семантика в этой карточке не утверждается. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Статически проверены все вхождения applyRangedMeleeBonus в текущих module/ и templates/. В JS есть только фабрика поля; формы его редактируют, но weaponAttack/professionMixin читают applyMeleeBonus. Настоящий WeaponData принимает раздельные значения; его default ranged при явном applyMeleeBonus:true становится true.

Ожидание основано на контракте перечисленных полей и потребителей, а не на сверке с книгой правил. Условия, методика и контрольные сценарии — [журнал сверок](../../analytics/code-audit/review-log.md#task-0003012).

Пределы: Отсутствие потребителя установлено для текущего кода, не для внешних модулей. Полный бросок и изменение флага в браузере не воспроизводились.

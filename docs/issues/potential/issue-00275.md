## Общее описание проблемы

Второй диалог собирает строку option с необработанным именем/локализованной подписью. Разметка в имени может создать новый пункт выбора.

## На что влияет в системе

Отображение и выбор средства защиты при специальных символах/разметке в имени.

## Почему это проблема

Подпись предмета становится структурой HTML; один исходный Item способен добавить option без соответствующего навыка/ID.

## Предложение по изменению

После согласования экранировать данные или формировать select штатным helper, сохраняя независимый Item ID. Исправление не согласовано.

## Воспроизведение и доказательства

Группа 28: имя `Blade</option><option value="fake">Injected`. При parry список содержит brawling, swordsmanship с Item ID и посторонний fake без ID. HTML разобран настоящим parse5; обычный пункт brawling выбран, поэтому ошибка fake-навыка в опыте не форсировалась.

Штатная очистка второго окна/браузер/XSS не проверены. issue-00266 — аналогичный механизм в отдельном оружейном диалоге, здесь другой производитель.

Использованы исходные методы и настоящие модели/Handlebars/Roll.parse; большинство исходов extendedRoll заданы на границе, группа 19 использует настоящий helper.

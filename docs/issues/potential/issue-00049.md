## Общее описание проблемы

applyStatusEffectToActor проверяет отсутствие ID в actor.appliedEffects, затем вызывает toggleStatusEffect без active=true. Отключённый эффект может отсутствовать среди appliedEffects, но core toggle находит его в actor.effects и удаляет.

## На что влияет в системе

Повторное применение статуса, документ которого уже есть у Actor, но disabled=true. Применение нового статуса и активного существующего отдельно проверены и ведут себя иначе.

## Почему это проблема

Название/назначение маршрута — применить статус при отсутствии активного воздействия. Удаление отключённого документа оставляет Actor без воздействия; ожидаемую политику повторного применения должен подтвердить пользователь.

## Предложение по изменению

Согласовать явно включающее поведение для имеющегося отключённого статуса и использовать соответствующий контракт ядра. Проверить новый, активный, отключённый и подавленный статусы, длительность и иммунитет. Исправление не согласовано.

## Воспроизведение и доказательства

В Actor-подмене effects содержал disabled=true эффект с единственным status 'fire', appliedEffects был пуст. Исходный applyStatusEffectToActor вызвал оригинальное тело Actor.toggleStatusEffect из Foundry 14.367. Перехвачен deleteEmbeddedDocuments('ActiveEffect',['disabled-fire']); создания/включения не было. Для нового статуса toggle выполнялся один раз, для уже активного — не вызывался.

**Пределы проверки:** Исходник ядра /opt/foundryvtt/client/documents/actor.mjs:547–582: поиск по _id либо единственному status не проверяет disabled, найденный эффект без active=true удаляется. Коллекции и БД подменены; реальная подготовка appliedEffects в мире не запускалась.

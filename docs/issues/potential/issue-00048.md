## Общее описание проблемы

Экспортируемый addStatusEffectChatListeners использует html.querySelector(...).each, затем оборачивает найденный элемент в jQuery и передаёт функции, ожидающей DOM querySelector. Эти требования к аргументам несовместимы.

## На что влияет в системе

Потенциальные внешние вызовы пакетного export. В module/, templates/ и packsJson/ внутренних вызовов этого имени не найдено. Штатный renderChatMessageHTML вызывает другой export напрямую.

## Почему это проблема

При передаче DOM Element querySelector возвращает одиночный Element без .each; при jQuery на самом html нет DOM querySelector. Экспорт существует, но указанная логика не обслуживает ни один из этих обычных типов входа.

## Предложение по изменению

Сначала определить, нужен ли пакетный export внешнему API. Если нужен — согласовать единый DOM-контракт и итерацию по сообщениям; иначе рассмотреть удаление отдельно. Исправление/удаление не согласовано.

## Воспроизведение и доказательства

Исходный export получил DOM-подмену, чей querySelector возвращает одиночный элемент. Синхронно получено html.querySelector(...).each is not a function. Поиск точного имени во внутренних исходниках дал только определение; переход к chatMessageListeners после $ также проверен чтением.

**Пределы проверки:** Это проверка невызванного внутри системы export, а не доказательство сбоя обычного чата. Внешние модули и макросы не обследованы; реальная DOM/jQuery-библиотека в этом сценарии не запускалась.

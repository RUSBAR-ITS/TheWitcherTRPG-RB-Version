## Общее описание проблемы

WeaponData.prepareDerivedData при непустом enhancementItemIds обращается к this.parent.actor.items без проверки наличия Actor. У отдельного Item parent.actor может быть null.

## На что влияет в системе

Подготовка отдельного оружия, содержащего ссылки на улучшения, завершается исключением до unwrapAssociatedDiagram. Возможный сценарий — копия ранее принадлежавшего Actor оружия; такой перенос в интерфейсе не воспроизводился.

## Почему это проблема

Модель оружия зарегистрирована как тип Item и используется также вне Actor. Невозможность разрешить локальные ID улучшений не должна автоматически означать невозможность подготовить весь документ; ожидаемое поведение для такого случая требует согласования.

## Предложение по изменению

После согласования определить поведение улучшений оружия без владельца: пропуск неразрешимых ссылок, очистка или иной механизм. Затем добавить проверку владельца в согласованном варианте. Исправление не согласовано и не выполнялось.

## Воспроизведение и доказательства

Настоящему WeaponData с enhancementItemIds=['e'] передан Item-контекст с actor:null. prepareDerivedData выбросил TypeError «Cannot read properties of null (reading 'items')». Контроль с коллекцией Actor разрешил существующий ID, пропустив отсутствующий.

Основание ожидаемого поведения указано выше; вывод не заменяет подтверждения пользователем. Окружение, подмены API и контрольные сценарии — [журнал сверок](../../analytics/code-audit/review-log.md#task-0003013).

**Пределы проверки:** Контекст родительского документа представлен фасадом. Открытие самостоятельного Item и перенос из Actor/компендиума в браузере не выполнялись.

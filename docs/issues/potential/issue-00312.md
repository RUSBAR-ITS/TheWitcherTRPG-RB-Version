## Общее описание проблемы

В двух правилах input.reliable-info/input.item-quantity и их :hover записано transition:all 0.3 ease. Число 0.3 без s/ms не задаёт CSS <time>; собственный переход не может быть применён как корректная декларация.

## На что влияет в системе

Плавность смены оформления полей количества и надёжности, в том числе в текущем оружейном инвентаре. Изменение значений Item этим CSS не выполняется; потеря/блокировка ввода не установлена.

## Почему это проблема

Файл явно задаёт переход и изменение фона при наведении, но нарушает грамматику времени. Остальные декларации блока остаются самостоятельными. Фактический переход может определяться стилями ядра или темы, что не проверялось.

## Воспроизведение и доказательства

C05 отрендерил настоящий HBS с одним оружием: оба поля присутствуют. PostCSS нашёл ровно две декларации all 0.3 ease. Грамматика transition требует <time> для длительности: [W3C CSS Transitions, shorthand](https://www.w3.org/TR/css-transitions-1/#transition-shorthand-property). Ожидается допустимое описание перехода; фактически в исходниках отсутствует единица времени.

Это проверка исходного значения по грамматике и наличия DOM-потребителя, а не CSS.supports/computedStyle в браузере. Отличается от issue-00310 (background-color) и issue-00311 (псевдоэлемент прогресса).

[Подробная методика и результаты](../../analytics/code-audit/review-log.md#task-0003050). Для CSS использованы исходные HBS/helpers и AST; для утилит — исходные тела, виртуальный FS и API/ClassicLevel-фасады.

## Общее описание проблемы

После применения статуса с длительностью включённая интеграция statuscounter вызывает `CONFIG.WITCHER.statusEffects.querySelector(...)`. Конфигурация определяет statusEffects как обычный массив; такого метода у него нет.

## На что влияет в системе

В сценарии активного statuscounter и ненулевой длительности возникает исключение при настройке счётчика. Само переключение статуса выполняется раньше, поэтому применение статуса и установка его длительности могут дать разный результат.

## Почему это проблема

Данные конфигурации и способ поиска элемента не согласованы. Вызов не доходит до установки значения и типа счётчика.

## Где конкретно локализована в коде

- [module/setup/config.js](../../../module/setup/config.js) — массив WITCHER.statusEffects, начиная со строки 2064
- [module/scripts/statusEffects/applyStatusEffect.js](../../../module/scripts/statusEffects/applyStatusEffect.js) — handleStatusCounterIntegration, строки 74–84; вызывается после toggleStatusEffect

## Предложение по изменению

Согласовать поиск статуса по id и проверку отсутствующего статуса/счётчика с фактическим API используемой версии statuscounter. Конкретное исправление не согласовано.

## Воспроизведение и доказательства

В Node загружен неизменённый config.js. Исходный handleStatusCounterIntegration выполнен в vm с подменой game.modules.get на активный модуль и duration=2. Получен `TypeError: CONFIG.WITCHER.statusEffects.querySelector is not a function`. Ожидаемое для обсуждения поведение — найти запись статуса и перейти к настройке счётчика. Следующий querySelector у результата EffectCounter.getAllCounters также требует проверки API, но до него выполнение не дошло.

Пределы проверки: использован исходный callback с подменой среды, реальный модуль statuscounter и браузер не запускались; сторонние изменения прототипов не исследованы.

## Общее описание проблемы

_onEditEffect проверяет element.value == 'on', а не тип поля. Текстовое поле имени с введённой строкой on проходит ту же ветвь, что checkbox, и передаёт element.checked вместо текста.

## На что влияет в системе

Имя воздействия в формах брони/улучшения может измениться с on на строку false. Повторяющийся код есть в других конфигурациях, но их полный анализ ещё не выполнен.

## Почему это проблема

Тип значения определяется содержимым текста, поэтому обычная строка изменяется при сохранении. Ожидаемое сохранение введённого имени обосновано type=text и StringField схемы itemEffect.name.

## Предложение по изменению

Согласовать определение checkbox по типу элемента/поля, сохраняя текстовые строки. Проверить одинаковые обработчики конфигураций и числовые поля отдельно. Предложение не согласовано; код не менялся.

## Воспроизведение и доказательства

Исходному _onEditEffect передан элемент type=text по форме: value='on', checked=false, data-field=name. Получен payload {'system.effects.fx.name':false}. Настоящая EnhancementData преобразовала это в name='false'. Контрольные вызовы для checkbox дали true, для percentage='25' сохранили строку 25 до очистки схемой.

Ожидаемое поведение и его основание указаны в разделе «Почему это проблема»; наблюдение не заменяет подтверждения пользователем.

**Пределы проверки:** Элемент и item.update подменены, настоящая модель полей использована. Сохранение и повторное открытие Item в мире не выполнялись.

## Общее описание проблемы

В character-header.hbs ссылка .open-rewards после иконки наград не закрыта тегом </a>. HTML5-парсер восстанавливает форматирующий элемент и создаёт дополнительные ссылки с тем же классом.

## На что влияет в системе

Структура DOM заголовка персонажа, набор элементов с обработчиком открытия наград, возможное размещение элементов flex-контейнеров.

## Почему это проблема

Для одной кнопки в результате разбора появляются три ссылки .open-rewards. Две дополнительные не содержат иконки и являются отдельными дочерними элементами блоков действий.

## Где конкретно локализована в коде

| Файл | Локализация |
| --- | --- |
| [templates/partials/character-header.hbs](../../../templates/partials/character-header.hbs) | Строка 58 — открывающий <a class="open-rewards"> без закрытия |
| [module/actor/sheets/WitcherCharacterSheet.js](../../../module/actor/sheets/WitcherCharacterSheet.js) | activateListeners:119 связывает все .open-rewards с _renderRewards |
| [styles/character-header.css](../../../styles/character-header.css) | Правила .char-actions / .action — связь восстановленных узлов с раскладкой |

## Предложение по изменению

Закрыть ссылку непосредственно после иконки и проверить DOM/раскладку и открытие наград в браузере. Исправление не выполнено.

## Воспроизведение и доказательства

Группа 20: настоящий Handlebars сформировал HTML заголовка, настоящий parse5 разобрал его по HTML5. Получены три a.open-rewards: первый внутри .improvement-points.action содержит иконку; второй непосредственно внутри .char-actions содержит только пробелы; третий внутри .death-section.action также содержит только пробелы. Счётчик смертей не вложен в эти пустые ссылки: утверждение о его клике здесь не делается. Браузерные геометрия, hit testing и фактический render не проверены.

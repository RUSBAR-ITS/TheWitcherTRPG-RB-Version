## Общее описание проблемы

_onNoteDelete напрямую передаёт event.currentTarget.dataset.noteIndex в Array.splice. Метод не проверяет наличие индекса, его целочисленность и принадлежность массиву.

## На что влияет в системе

Выбор удаляемой записи Actor.system.notes при некорректном аргументе. Текущие шаблоны формируют индекс из @index; обычный клик с повреждённым индексом не воспроизведён.

## Почему это проблема

Некорректный индекс может удалить существующую заметку вместо отказа: undefined и 'bad' приводятся к 0, '-1' выбирает последний элемент, '1.5' — индекс 1. Метод отправляет весь изменённый массив на сохранение. '99' ничего не удаляет, но всё равно вызывает update.

## Предложение по изменению

После согласования проверять Number.isInteger преобразованного индекса и границы 0 ≤ index < notes.length, отдельно отбрасывая отсутствующее/пустое значение. При неверном индексе не изменять массив и не выполнять запись. Решение о стабильных ID записей в задачу не входит. Исправление не выполнялось.

## Воспроизведение и доказательства

Группа 04, настоящий метод и CharacterData с [A,B,C]: undefined/'bad' → [B,C]; '-1' → [A,B]; '1.5' → [A,C]; '99' → [A,B,C]. Во всех случаях update перехвачен. Группа 03 проверила штатные '0'/'2' и пустой массив. Нештатные dataset переданы программно; гонка устаревших индексов между окнами не проверена.

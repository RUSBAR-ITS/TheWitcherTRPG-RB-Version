## Общее описание проблемы

Девять изменений Difficult передают объект JSON-строкой в system.combatEffects.turnStartEffects.bleed/suffocation/acid с legacy mode=2. Штатная миграция Foundry 14 успешно преобразует строку в объект, mode в add и задаёт initial. Однако поле каждой записи — SchemaField, чей _applyChangeAdd возвращает прежнее значение. В исходном пустом turnStartEffects запись не появляется.

## На что влияет в системе

Семь Item могут добавить Actor статус bleed, один — suffocation, но [applyCombatEffects](../../../module/scripts/combat/generalCombatHook.js):41–45 читает Object.values(turnStartEffects), а не statuses. На этих исходных данных обработчик не получает damage.amount и не вызывает урон. У исходного Torn Stomach кислотная запись также отсутствует, числовые штрафы навыков при этом применяются отдельно.

## Почему это проблема

Экспорт явно задаёт amount и тип операции для передачи данных обработчику начала хода, но контракт операции ADD реального SchemaField не создаёт эту структуру. Наличие ActiveEffect и статуса не обеспечивает обещанное полем damage воздействие. Вывод основан на маршруте данных, без проверки правильности amount по правилам.

## Предложение по изменению

После подтверждения согласовать формат воздействия для записей turnStartEffects в Foundry 14 и способ их совмещения. Отдельно решить, должна ли новая запись заменять одноимённую, объединяться с ней или накапливаться. Диагностический override подтверждает причину, но сам по себе не является согласованным исправлением всех эффектов.

## Воспроизведение и доказательства

Настоящие BaseActor/CharacterData, BaseItem/CriticalWoundData и WitcherActiveEffect подготовлены с core allApplicableEffects/applyActiveEffects в фазах initial/final. Для всех девяти исходных Item getFieldForProperty вернул SchemaField, мигрированное value — объект, turnStartEffects остался {}. Реальный applyCombatEffects не вызвал перехваченный Actor.applyDamage; statuses при этом содержит семь bleed, один suffocation, у Torn Stomach пуст.

Положительные контроли: только в памяти у копий saPd4IMUCv5qZE60, tiVrEesPSzZ64HpZ и 5gnx9xNF52ap9PYi mode=2 заменён на mode=5. Та же подготовка создала по одной записи, ignoreArmor="true" очистился в boolean true, spDamage="0"/default — в число 0. Реальные generalCombatHook → applyDamageFromStatus → DamageInstance передали amount=2/3/4 в перехваченный Actor.applyDamage. Тип acid на этом следующем этапе потерян — прежняя [issue-00021](issue-00021.md). Исходный ADD до этой ветви не доходит; две причины разделены.

Основной сценарий проверяет все 201 changes, дополнительный — 43 утверждения по девяти источникам и трём контролям. Полный lifecycle, Combat update, таймеры/registry, HTML, чат, конечные HP/броня и установленная БД не запускались; клиентское окружение и операции записи — фасады. Поэтому вывод ограничен текущими экспортами и проверенным ядром 14.367.0, не переносится на Foundry 13 или неизвестное содержимое packs/.

Поиск по SchemaField, turnStartEffects, периодическому урону и реестру issues не выявил описания этой причины. Прежние issue-00006/00021/00022/00299 касаются других участков обработки уже существующих записей.

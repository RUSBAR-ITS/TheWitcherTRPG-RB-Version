# issue-NNNNN — Название проблемы

Шаблон: после согласования регистрации создать карточку в `potential`, назначить следующий общий номер и заполнить поля. Этот файл не является зарегистрированной проблемой. Порядок работы — в [правилах](../../rules/issues.md).

| Поле | Значение |
| --- | --- |
| ID | `issue-NNNNN` |
| Дата регистрации | ГГГГ-ММ-ДД |
| Дата последней проверки | ГГГГ-ММ-ДД или «не проверено» |
| Ветка | Название ветки |
| Коммит | Полный хеш проверяемого коммита; указать незакоммиченные изменения, если они влияют на проверку |
| Версия Foundry VTT | Проверенная версия и источник сведений либо «не установлена» |
| Окружение | Существенные условия: ОС, браузер, мир, модули; неизвестные данные отметить явно |
| Связанная задача | Ссылка на согласованную задачу либо «не создана» |

Статус определяется каталогом карточки и отражается в [реестре](../README.md).

## Общее описание проблемы

Какое поведение наблюдается, при каких условиях. Явно отделить проверенные факты от предположений.

## На что влияет в системе

Какие пользовательские сценарии, документы, расчёты или компоненты затронуты. Подтверждённое и предполагаемое влияние описать отдельно.

## Почему это проблема

Какому ожидаемому поведению или согласованному требованию противоречит наблюдение. Указать основание ожидания. Если противоречие ещё не подтверждено, записать, что именно нужно проверить.

## Где конкретно локализована в коде

Относительные ссылки на файлы, поля, функции или обработчики; при необходимости — номера строк для указанного коммита. Различать место проявления и установленную причину. Если точная локализация неизвестна, так и написать.

## Предложение по изменению

Предлагаемый способ исправления, затрагиваемые компоненты и ожидаемый результат. Отметить, что предложение не согласовано, если согласования ещё нет. При недостатке сведений описать необходимую проверку; не придумывать решение.

## Воспроизведение и доказательства

- **Условия:** версия, данные и настройки, необходимые для проверки.
- **Шаги:** последовательность действий, достаточная для повторения наблюдения.
- **Ожидаемый результат:** что должно происходить и на каком основании.
- **Фактический результат:** что действительно получено; если сценарий не выполнялся, указать это.
- **Доказательства:** вывод команд, сообщения, ссылки на код или другие проверяемые материалы.
- **Пределы проверки:** что не проверялось; отдельно перечислить только предлагаемые проверки.

## Подтверждение и закрытие

| Решение | Дата и результат |
| --- | --- |
| Согласование регистрации пользователем | Дата и содержание согласованного действия |
| Подтверждение проблемы пользователем | Не получено / дата и решение |
| Согласование исправления | Не получено / дата, объём и ссылка на согласованный документ |
| Подтверждение закрытия пользователем | Не получено / дата и решение |

- **Основание закрытия:** пока не определено / исправлено / иная подтверждённая причина с пояснением.
- **Выполненные изменения:** не выполнялись / описание и ссылки.
- **Проверки результата:** не выполнялись / команды или сценарии, версия, фактические результаты и ограничения.

До подтверждения закрытия пользователем карточка остаётся в текущем каталоге. Предлагаемое закрытие не записывается как состоявшееся.

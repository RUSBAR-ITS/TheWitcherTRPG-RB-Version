## Общее описание проблемы

Во всех трёх Item Fractured Leg (Right) вложенный эффект имеет name=Fractured Leg (Left). Поле location самого Item правильно указывает rightLeg, но метод формирования формулы использует имя ActiveEffect и сообщает о левой ноге.

## На что влияет в системе

При включённом displayRollsDetails подпись источника штрафа в формуле dodge отображает другую сторону тела. Аналогичный путь читает имя эффекта для athletics; полный бросок athletics не воспроизводился. Числовые значения changes применяются независимо от имени и не были признаны неправильными этой проверкой.

## Почему это проблема

Пользователь получает неверное объяснение происхождения применённого штрафа: у Actor в сценарии имеется только травма правой ноги, а сформированная подпись говорит о левой. Это несогласованность Item и эффекта в фактическом выводе, независимо от чисел и правил лечения.

## Предложение по изменению

После подтверждения согласовать корректные названия эффектов этих трёх Item и проверить подписи навыковых модификаторов для обеих ног. Числа штрафов, origin и общую механику лечения не менять под видом исправления подписи.

## Воспроизведение и доказательства

Каждый Item загружен настоящими BaseItem/CriticalWoundData, эффект — WitcherActiveEffect/WitcherActiveEffectData с ядром Foundry 14.367.0. Core applyActiveEffects применил соответствующие изменения. Настоящий modifierMixin.addActiveEffects('dodge') с реальным CONFIG.WITCHER.skillMap и displayRollsDetails=true вернул:

| Состояние Item | Фрагмент формулы |
| --- | --- |
| none | ` +-3[Fractured Leg (Left)]` |
| stabilized | ` +-2[Fractured Leg (Left)]` |
| treated | ` +-3[Fractured Leg (Left)]` |

Список appliedEffects задан из реальных активных эффектов контрольного Actor; настройки/клиентское окружение — фасады. Бросок, отправка сообщения и браузер не запускались. Повторяющийся ID эффекта между разными Item не объявлен коллизией; origin=Item.r34NuXwHfPGZCpTu — отдельная мировая ссылка, существование адресата не проверялось.

Поиск по Fractured Leg, ID трёх Item, именам и прежнему реестру issues не обнаружил дубля этой ошибки подписи. Различие числовой последовательности лечения справа и слева сохранено в аналитике; соответствие значений рулбуку здесь не установлено.

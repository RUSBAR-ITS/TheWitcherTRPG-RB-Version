## Общее описание проблемы

Sprained Leg (Left - Treated), ID f7NaW1AMnrSLGkd3, имеет system.location=leftArm. У его исходной и стабилизированной форм location=leftLeg. Переход followUp ведёт к этому существующему treated Item, поэтому при лечении сохраняется несогласованное поле.

## На что влияет в системе

[Список травм](../../../templates/partials/crit-wounds-table.hbs) выводит локацию через lookup по system.location, отдельно от имени Item: леченая левая нога получает подпись левой руки. Любой дальнейший читатель location получает leftArm. Конкретный сторонний модуль или макрос не проверен.

Штраф SPD у Item применяется по собственному пути changes и от location не зависит. Первичный автоматический выбор applyCritWound отсеивает treatment=treated, поэтому этот случай не доказан как нарушение первоначальной выдачи травмы.

## Почему это проблема

Внутри одной явно связанной цепочки none → stabilized → treated меняется анатомическая локация, хотя имя конечного документа продолжает обозначать левую ногу. Это несогласованность структурных данных и их вывода; вывод не требует сверки чисел с рулбуком. Требуемое исправление остаётся решением пользователя.

## Предложение по изменению

После подтверждения назначения конечного документа согласовать location=leftLeg и проверить цепочку, подпись локации и неизменность эффекта. Не переносить location автоматически между всеми followUp без отдельного решения: общий контракт допускаемых переходов не устанавливался этой проверкой.

## Воспроизведение и доказательства

Все три JSON загружены настоящими BaseItem и CriticalWoundData с strict=true на Foundry 14.367.0. Поле leftArm конечного Item сохраняется после очистки. Реальный treat стабилизированной травмы передал в перехваченный createEmbeddedDocuments адресата f7NaW1AMnrSLGkd3, затем инициировал удаление исходника. Записи удерживались Promise; мир и БД не изменялись. Штраф SPD=-1 применился реальным WitcherActiveEffect/core NumberField; подпись локации установлена статически по шаблону, не по снимку браузера.

Поиск по имени и ID не обнаружил прежней карточки этого дефекта. [issue-00324](issue-00324.md) касается других документов Complex и первичного выбора среди кандидатов; здесь ошибочное поле конечного Simple Item с иными последствиями. [issue-00121](../potential/issue-00121.md) описывает самостоятельную проблему ожидания замены.

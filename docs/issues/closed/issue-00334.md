## Общее описание проблемы

В интерфейсе травм и ActiveEffect смешаны несколько независимых причин: два рендера одного списка травм; повтор одного документа в подготовленных категориях эффектов; отсутствующее действие раскрытия описания Item-эффекта; обращение формы к отсутствующему полю; повторное добавление элементов редактора и обработчиков кнопки при сохранении части DOM.

Общая задача ограничена представлением и маршрутизацией UI-действий. Сам факт двух строк не доказывает двукратное применение числового эффекта. Частичный рендер — поддерживаемая возможность Foundry, но для 00055/00230 обычное пользовательское действие, которое вызывает проблемный частичный рендер, пока не установлено.

## На что влияет в системе

- Вкладка эффектов Character и Monster: количество строк травм/эффектов, описание, элементы лечения и заживления.
- Вкладка ActiveEffect в конфигурации предмета, включая наследников базового окна: чтение описания эффекта.
- Редактор ActiveEffect: системные поля, кнопка мастера, списки подсказок и сохранность введённых значений при обновлении частей окна.
- Конвертер валют в инвентаре Character: число окон, открываемых одним нажатием.

## Почему это проблема

Один игровой документ должен иметь одну строку в данном списке, одно нажатие — одно предусмотренное действие. Повторный рендер не должен накапливать обработчики или служебные элементы. Форма должна показывать существующие поля своей модели, а предусмотренное раскрытие описания — работать в том окне, где отображено.

Ожидаемое исправление не меняет схему ActiveEffect/Item, расчёт характеристик, правила лечения, передачу улучшений, курсы или формулу обмена валют. Миграция миров и пересборка компедиумов для этой задачи не нужны.

### Проверенные особенности потребителей

1. [registerSheets.js](../../../module/setup/registerSheets.js) регистрирует Character/Monster V2. WitcherActorSheetV1 в регистрации не найден; общая примесь всё равно должна сохранять корректный контракт для его существующего getData. Специальную поддержку старой Foundry, старых миров или миграций не добавляем.
2. Текущий crit-wounds-table включён только из общего V2 tab-effects и заранее загружен через [handlebars.js](../../../module/setup/handlebars.js). Следовательно, можно перенести в него расширенную строку с описанием и оставить единственное включение; пути и предзагрузка останутся прежними.
3. effect-part используется общим V2 tab-effects, старым monster-sheet и Item activeEffectConfiguration. Новое действие раскрытия будет передаваться только из контекста Item-конфигурации; существующий Actor-listener останется единственным владельцем Actor-клика.
4. От WitcherConfigurationSheet наследуются конфигурации Consumable, Properties и Profession. Новое действие должно добавиться к их унаследованным actions, сохранив create/toggle/edit/delete и собственные действия наследников.
5. Примесь **листа** currencyConverterMixin подключена только к WitcherActorSheet V2. Примесь **Actor-документа** с тем же именем — другой файл, который занимается обменом. Их нельзя смешивать.
6. Кнопка `.open-currency-converter` присутствует в текущем Character tab-inventory; Monster использует другой шаблон инвентаря. Наследование action базового класса не является поручением добавлять монстру новую кнопку.

## Предложение по изменению

Ниже конкретный предлагаемый план. Создание этой карточки разрешено; реализация плана ещё не начата и требует отдельного поручения пользователя.

### U01 — один рендер травм: 00054

1. В существующем crit-wounds-table сделать единственной реализацией строку из расширенного блока tab-effects: details/summary и prepared enriched-описание, тяжесть, состояние, локация, daysHealed/healingTime и кнопка лечения.
2. Из tab-effects убрать второй ol/each. Оставить заголовок, кнопку добавления и ровно одно включение partial.
3. Сохранить `data-item-id`, `data-type`, `data-field`, `data-action="treatCriticalWound"`, `data-id` с UUID и CSS-классы; оставить текущую выборку documentsByType. Не добавлять фильтр stored/скрытия травм и не менять порядок документов.
4. Использовать уже подготовленный `context.criticalWounds[uuid].enriched`; не вводить дополнительный async-запрос и не записывать enriched HTML в Item.

### U02 — уникальность в списке эффектов: 00165

1. В Actor prepareActiveEffectCategories завести локальный учёт уже обработанных полных UUID; сохранить первый экземпляр и исходный порядок входного потока.
2. Повтор того же UUID не добавлять ни в одну категорию второй раз. Для объекта без UUID допустим резервный учёт по его идентичности, но не по имени или локальному id.
3. После проверки уникальности оставить прежние условия isDisabled, isTemporaryItemImprovement/isAppliedTemporaryItemImprovement, isTemporary и passive. Suppression по-прежнему учитывает шаблон.
4. Не изменять входной массив/генератор, реальные документы, transfer/isTransferred, allApplicableEffects, выборку stored Items и Item prepareActiveEffectCategories. Разные эффекты с одинаковыми id под разными Item должны остаться разными строками.
5. Общая точка автоматически охватывает V2 и существующий вызов V1; отдельный новый слой совместимости не создаётся.

### U03 — раскрытие описания в настройках предмета: 00056

1. В Item-конфигурации добавить именованное действие, например `displayEffectDescription`, с локальным обработчиком `(event, element)`. Использовать переданный action-element, не event.currentTarget делегированного listener.
2. В её контекст передать имя действия; общий effect-part выводит соответствующий data-action на `.effect-display` только при наличии этого значения. Внутри each обращаться к корневому контексту, чтобы флаг не терялся.
3. Обработчик находит ближайшую `.effect-row` и её `.effect-description`, проверяет непустое HTML-содержимое и переключает `invisible`. Не обновляет документ и не вызывает редактор. Пустое описание не раскрывает пустую область.
4. Сохранить существующий Actor-listener. Не добавлять ему второй action и не переносить остальные Actor CRUD-listeners на V2 в рамках этой задачи.
5. Сохранить create/toggle/edit/delete и их семантику владения. Новый action наследуют Item-конфигурации; повторные рендеры не создают новых ручных подписок.

### U04 — поля системной вкладки по схеме: 00053

1. Обернуть только formGroup applyAfterCalculations условием наличия `systemFields.applyAfterCalculations`.
2. Обычный эффект продолжает показывать поле; временное улучшение его не показывает. Остальные существующие условия applySelf/applyOnTarget/applyOnHit/applyOnDamage сохранить.
3. Не добавлять Temporary-модели поле, значение по умолчанию, фазу или миграцию. Не менять _preUpdate ради прохождения этой проверки.

### U05 — повторяемое обновление редактора: 00055

1. Разделить внутри существующего редактора обеспечение кнопки мастера и обеспечение datalist. Операции должны быть безопасны при полном и частичном рендере.
2. Для существующей секции changes найти или создать одну принадлежащую этому окну кнопку wizard возле штатного addChange; повторный вызов не вставляет ещё одну. Отсутствие секции/кнопки обрабатывать без исключения.
3. Назначить datalist уникальный ID на экземпляр окна, использовать его только внутри текущего окна. Найти или создать один список; обновлять его содержимое без накопления копий. Не удалять элементы чужих окон/модулей глобальным селектором.
4. После рендера назначать ссылку `list` актуальным полям ключей, включая вновь появившиеся строки. Простой флаг «инициализировано один раз» недостаточен: DOM поля может быть заменён.
5. Сохранить текущий источник каталога CONFIG.Actor/CONFIG.Item, порядок подсказок и подписи. Исправление выбора схемы переносимого эффекта (00051) сюда не включается.
6. Не пересоздавать пользовательскую форму ради очистки дублей и не вызывать submit/update. Введённые, но ещё не сохранённые key/value/priority должны оставаться на месте, когда changes не перерисовывается.

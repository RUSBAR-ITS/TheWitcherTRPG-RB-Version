## Общее описание проблемы

temporaryHp.value дописывается к min(rollOver,maxRollOver) строкой; Roll.evaluate вызывается только если строка содержит d. Для +2 строится value:5+2 внутри JSON.

## На что влияет в системе

Данные эффекта временных HP для разрешённого схемой строкового выражения без кубов.

## Почему это проблема

StringField принимает +2, но итоговая строка не является валидным JSON/числовым value. Это другая причина, чем кавычка в имени issue117.

## Предложение по изменению

Согласовать синтаксис количества HP и вычислять допустимое выражение до сериализации; собирать структуру JSON безопасно. Решение и исправление не согласованы.

## Воспроизведение и доказательства

Группа 17: при rollOver7/cap5 и value=+2 сформировано {"name":"Aid","value":5+2}; JSON.parse бросает SyntaxError. Для d6 используется реальный Roll; core миграция не вычисляет арифметику malformed JSON. Сам эффект в БД не создавался.

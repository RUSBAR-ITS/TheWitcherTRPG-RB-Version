<a id="decision-00058"></a>
## Принятое правило 2026-09-18 — .00058

Пользователь согласовал автопровал обратного испытания по **суммарному порогу после всех применимых поправок**: для условия `результат <= T` при T<=0; для строгого `результат < T` при T<=1. При T=1 нестрогое сравнение ещё допускает успех на1. Порог не поднимать до минимального значения характеристики. Автопровал даёт явный success=false/сообщение о провале; критический результат не обходит эту границу. Бонус к порогу учитывается до принятия решения об автопровале.

Отсутствие порога — отдельное состояние, не отрицательное число. Реализация и перевод всех входов описаны в [TASK-0010.007](../../tasks/task-0010-parameter-limits.md#task-0010007) и [.008](../../tasks/task-0010-parameter-limits.md#task-0010008); техническая форма отсутствия порога проверяется в .002. С30/Б08 покрывают `<`/`<=`,−1/0/1/2, бонус до границы, критический0 и отсутствие порога. Обычные атаки/защиты этим правилом не меняются.

## Уточнение плана 2026-09-18 — .00057

По поручению пользователя сверены русская основная книга `core_rulebook.md` в архивном каталоге `assets/books` (с.47: «Дополнительные параметры» / «Обмануть смерть»; с.162: «Испытания против смерти») и [официальное уточнение STUN, The Sage’s Answers, Part 18](https://rtalsoriangames.com/2018/09/21/the-sages-answers-part-18/).

Книга задаёт успех при результате 1d10 **ниже порога**; для испытаний против смерти действует накапливающийся −1. Удача увеличивает порог. Официальное уточнение подтверждает вычитание штрафа Stun (−X) из порога конкретного испытания. В этих разделах нет требования обрезать итоговый порог до1 или считать отрицательное число отсутствием проверки. Нижняя граница характеристики из TASK-0010 — другое понятие.

**Вывод из этих правил:** для обычного испытания против смерти без дополнительных поправок бросок 1d10 при пороге1,0 или−1 не может дать успех; результат должен быть показан как провал. Это вывод из диапазона куба и строгого сравнения, а не найденная отдельная цитата об отрицательном пороге. Не вводить автоматическую смерть при одном изменении поля: речь об оценке выполненного испытания и его отображении. Учитывать итоговый порог после допустимых бонусов, включая Удачу.

**Предложение после сверки, до реализации:** отделить отсутствие порога в RollConfig от любого числового порога, включая −1, и сохранить строгое сравнение обратного испытания. Например, отсутствие обозначать null; точный контракт выбрать при проверке всех вызывающих мест .002/.007–.008. Не менять попутно критические правила других испытаний, у которых сейчас showCrit=true. Death Save сейчас явно использует showCrit=false. Тесты: пороги−1/0/1/2, равенство, повышение порога бонусом, бросок без порога и обычные атака/защита.

Сверка выполнена по текстам и текущим исходникам `deathSaveMixin`, `rollConfig`, `extendedRoll`; новых игровых тестов не было. [TASK-0010](../../tasks/task-0010-parameter-limits.md#related-issues) содержит этот пункт как предложение по итогам сверки, не как уже согласованное новое техническое решение.

## Общее описание проблемы

Спасбросок смерти вычисляет min(база,10)−deathSaves без нижнего ограничения. При отрицательном результате extendedRoll пропускает весь блок сравнения, поскольку проверяет threshold>=0. Аналогичная граница доступна спасброску характеристики с отрицательным value.

## На что влияет в системе

Результат спасбросков состояния при большом счётчике deathSaves или отрицательной характеристике: сообщение имеет кубик и подпись порога, но не получает success/rollOver и итоговую надпись сравнения.

## Почему это проблема

Отрицательная рассчитанная игровая величина смешивается с режимом общего броска без порога. Для спасброска по числовому порогу результат должен быть определён согласно согласованному правилу; отказ от сравнения не выражен отдельным намерением вызывающего метода.

## Исправление неизменяющей записи — 2026-09-17 / 14.3.1.00030

По согласованию пользователя исправлен остаток М05, воспроизведённый на .00029. Множитель 1 допустим. После `checkIfItemHasRollTable`, только для `not-found`, результат сравнивается с `item._source.system.quantity`: поле количества — StringField, поэтому вычисленное число приводится к строке. Если сохранённое количество уже совпадает, `update` не вызывается, предмет засчитывается обработанным и цикл продолжается. Сравнение с исходными данными не подменяется сравнением с подготовленным значением, которое может быть изменено эффектами. Проверка генератора остаётся перед сравнением: одинаковое количество не отменяет выполнение таблиц.

При действительно нужной записи сохраняются `await item.update`, проверка возвращённого документа и обработка исключения. `undefined` в этой ветке остаётся отказом; экспорт останавливается с отчётом и сохранённой частичной добычей. Контракт Foundry не меняется: Document.update может вернуть undefined при пустом diff либо отмене. Локализация: [WitcherMonsterSheet.js](../../../module/actor/sheets/WitcherMonsterSheet.js), #exportLoot, строки 214–224. Единственная правка игрового кода — условие перед записью и поясняющий комментарий.

**Проверено без Foundry:** синтаксис JS; шесть проверок настоящего обработчика из полного модуля в VM. Подменены API Foundry, диалог, Item/Actor-записи, Roll и обработка генератора. Проверены: неизменная стопка → формула → генератор при множителе 1; различие исходного и подготовленного количества; undefined и исключение при нужной записи после уже обработанного предмета; множитель 2 и сумма отдельных бросков; ожидание записи до render. До правки — 3/6, после — 6/6. Фасад Item.update воспроизводит undefined при пустом изменении; сервер и реальные таблицы здесь не запускались.

Артефакты: `/var/lib/foundryvtt/Data/work-cat/witcher-loot-noop-20260917/` (`loot.test.mjs`, `before-tests.tap`, `offline-tests.tap`). Команда: `node --experimental-vm-modules --test .../loot.test.mjs`.

## Общее описание проблемы

#exportLoot запускает async callback через newLoot.items.forEach, не собирая его Promise, затем ждёт только render. Внутри callback также не ожидается item.update.

## На что влияет в системе

Момент завершения экспорта, первоначальное содержимое открытого листа добычи и получение ошибок обработки предметов.

## Почему это проблема

Завершение action не означает, что количества вычислены или генераторы таблиц обработаны. Ожидание render не заменяет ожидания записи Item.

| [module/item/witcherItem.js](../../../module/item/witcherItem.js) | checkIfItemHasRollTable: 257–315 — ожидается только внутри отдельного callback |

## Предложение по изменению

После согласования дожидаться полного набора операций обработки Item и их записей, определить обработку ошибок частичного экспорта. Код не менялся.

## Воспроизведение и доказательства

Группа 20: отдельно удержаны Promise проверки таблицы и Promise update одного Item с quantity='3' при множителе 2. В обеих ветках action уже завершён и render вызван, количество ещё '3'. После разрешения удержанной операции оно становится 6. Записи/окно подменены; серверные гонки не воспроизводились. Это внешний уровень экспорта, отдельный от issue-00040 о потере увеличения внутри генератора.

## Общее описание проблемы

applyTemporaryItemImprovements копирует исходный эффект через spread, затем полностью заменяет его system объектом из трёх флагов. Хранящийся в исходном system.changes список не попадает в запрос createEmbeddedDocuments.

## На что влияет в системе

Перенос временного улучшения на выбранное оружие и последующее применение WitcherItem.applyActiveEffects.

## Почему это проблема

Получатель исполняет effect.system.changes. Запрос создания содержит isTransferred/applySelf/applyOnTarget, но не содержит исходных изменений. Успешное создание оболочки эффекта само по себе не передаёт её модификаторы.

## Предложение по изменению

Согласовать сохранение полей system при замене служебных флагов и проверить передачу через все вызывающие пути. Полный пофайловой разбор цепочки выполнен в TASK-0003.009; текущая сквозная сверка TASK-0004.005 сопоставила передачу, модель, Item-применение и сообщение. Исправление не согласовано.

## Воспроизведение и доказательства

Исходный applyTemporaryItemImprovements выполнен с эффектом типа temporaryItemImprovement, содержащим одно современное изменение в system.changes. Диалог вернул выбранное оружие; createEmbeddedDocuments и чат перехвачены. В переданном system остались только isTransferred:true, applySelf:false, applyOnTarget:false; changes отсутствует, исходный массив по-прежнему содержит одну запись. Проверены данные запроса, а не создание документа или миграция legacy top-level changes в живом мире.

[Сценарии и перекрёстная сверка TASK-0003.008](../../analytics/code-audit/review-log.md#task-0003008). Тела проверяемых функций сохранены; внешние действия подменены. Изменений системы и игровых документов не выполнялось.

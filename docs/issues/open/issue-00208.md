## Общее описание проблемы

Поле multiple имеет type=number без min, callback возвращает строку, а экспорт не проверяет положительное целое число. Отрицательный множитель умножает обычные количества, но не запускает цикл бросков для количества-формулы.

## На что влияет в системе

Количество предметов новой добычи и согласованность обработки фиксированных количеств и формул.

## Почему это проблема

Для multiple=-2 обычное количество 2 превращается в -4, а '1d6' — в 0. Эти результаты не представляют единое число экземпляров монстра.

## Предложение по изменению

Согласовать допустимые значения multiple (включая 0), валидировать их до создания Actor. Код не менялся.

## Воспроизведение и доказательства

Группа 19: настоящий action с контролируемым возвратом prompt; '-2' даёт -4/0, '0' и '' дают 0/0. Дополнительно программно переданное '1.5' даёт 3 для quantity2, но два броска (2+3=5) для '1d6'. Дробный ввод в реальном браузере не доказан: у number без step есть нативное ограничение шага. Отрицательный ввод не ограничен min. Dialog, Actor/Item-запись подменены, сохранение в БД не проверялось.

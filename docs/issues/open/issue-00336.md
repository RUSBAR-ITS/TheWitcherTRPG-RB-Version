## Общее описание проблемы

При первой установке критической травмы с вложенным активным эффектом Item и AE сохраняются, штраф применяется, но операция возвращает `failed/uncertainWrite`. Пользователь получает сообщение, что запись травмы не удалось подтвердить.

## На что влияет в системе

Результат операции получения травмы и уведомление пользователя. В воспроизведении травма ноги уже снижала Скорость 8 → 6. Ложное сообщение может побудить повторить успешно выполненное действие. Отсутствие записи в БД этим сообщением не подтверждается.

## Почему это проблема

Проверка результата считает предусмотренную инициализацию часов AE несовпадением стадии. Успех должен подтверждаться по ожидаемым сохраняемым данным; реальные отклонения записи при этом должны обнаруживаться.

## Где конкретно локализована в коде

- [criticalWoundOperations.js](../../../module/item/criticalWoundOperations.js): `writeStage`/`prepareWoundStage` готовят AE с null start; `stageMatches` сравнивает все поля AE, кроме `_stats`.
- [WitcherActiveEffect._preCreate](../../../module/activeEffect/witcherActiveEffect.js): для эффекта предмета владельца заполняет отсутствующий start и duration через [initializeEffectStart](../../../module/activeEffect/effectApplication.js).
- [damageMixin.applyCritWound](../../../module/actor/mixins/damageMixin.js) и ручная установка вызывают общий сервис; `reportWoundResult` сообщает ошибку по его результату.

## Предложение по изменению

[Проект .010](../../tasks/task-0012-temporary-hp.md#task-0012010): до первого create заполнить отсутствующие часы подготовленных AE тем же helper, отправлять и проверять одинаковые ожидаемые данные. Сохранить строгий stageMatches и реальные ошибки записи, однократность коррекции длительности и исходный шаблон. Нужны проверки настоящего `_preCreate` и игровое повторение; замену существующей стадии не переписывать.

## Воспроизведение и доказательства

На .00139 вызов `applyCritWound` для leftLeg/simple при отсутствии соответствующей травмы дал failed при сохранённом Item/AE и работающем штрафе. Аналогичный прямой вызов installWound воспроизведён у monster. В сравнении запроса и результата из сравниваемых полей отличался `effects[0].start`: null → объект времени/боя. Добавленный ядром ownership уже исключён из сравнения.

[Протокол .008](../../analytics/task-0012-checks.md#browser-00139); серверные артефакты `work-cat/witcher-task0012-browser-20260920/wound-probe.json`, `wound-game.json`, `wound-ui.json` относительно Data. Повтор существующей травмы и проверенные переходы стадий работали. Это не принятая [гонка двух клиентов](../../documentation/known-limitations.md): ошибка возникла в одной последовательной операции. Проверка более старой версии в запущенном мире не выполнялась; её происхождение не приписывается без такого доказательства исключительно TASK-0012.
